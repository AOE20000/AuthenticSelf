## M0 先补两处短板（预计最小，收益立刻可见）

### M0.1 检索改成三因子

现在 `recall()` 只算二元组重叠（=只有"相关"）。`salience` 字段在库里躺着没用。

```
score = w_rec·recency + w_sal·salience + w_rel·重叠度
```

- recency：指数衰减（半衰期可配，默认 7 天）
- salience：已有字段，写入时定
- 三者 min-max 归一后加权

**验收**：同一条线索下，一条"很相关但三个月前"的记忆，不再稳定压过"中等相关但昨天刚写、显著度高"的记忆。

**来源**：Generative Agents（三因子检索是它的核心贡献）。

### M0.2 遗忘状态补全

现在只有 `active / suppressed`。补两种，**都必须指向替代者**：

| 状态 | 语义 | 默认检索 | 指针 |
|---|---|---|---|
| `merged` | 被更完整的新条目吸收 | 否 | → 新条目 |
| `superseded` | 被更新的事实取代 | **是**（历史常有价值） | → 新条目 |
| `suppressed` | 人为屏蔽，无替代 | 否 | — |

**验收**：写入"搬到北京"后，旧的"住在上海"变成 `superseded` 且指向新条目；默认检索两条都出，`latest_only` 只出新。

**来源**：Mem0 Dream 的 merge / supersede / synchronize 三状态。

## M1 遗忘五区（F1–F3）

### M1.1 补验压缩本体

上一次压缩只验证到"触发"，`--print` 模式下没观测到真正执行。需要一次能跑完压缩的会话（TUI 或长会话）。

**验收**：能看到 `compaction` 条目、上下文 token 明显下降、且**点名保留的条目仍在**。

### M1.2 五区分类

压缩时把 `branchEntries` 分成五类（不可移出 / 计划 / 工作区 / 可压缩 / 索引），按优先级决定保谁。

**验收**：人为构造一段"含承诺 + 已解决分支"的对话，压缩后承诺还在、已解决分支被合并。

### M1.3 索引行

被移出的内容留一行 `[已归档｜日期｜标题] 细节不在上下文内，可按时间检索。`——让模型**知道自己忘了什么**。

**验收**：压缩后模型能说出"我记得有这件事，但细节不在上下文里"。

### M1.4 补救 R2–R3

- R2：按线索取回情景摘要
- R3：按归档指针回原文（`SessionManager.listAll` + 会话文件）

## M2 交涉通道

### M2.1 `memory` 单一触发（C4 裁定）

一个工具，只收自然语言 + 可选目标：

```
memory({ say: "把上周那个 Redis 的结论忘掉", target?: "Redis 缓存选型" })
```

`kind`（forget/revise/remind/link/unlink）由旁路解析，主 AI 不需要知道枚举。

**验收**：主 AI 说"别再提 X"，下一轮真的不注入了。

### M2.2 变更门控：delta-clamp + 观察窗

现在只有"事后回滚"。补两样（**来源：MSCP 的 delta-clamp + CT Toolkit 的 staged approval**）：

1. **幅度上限**：单次变更最多影响几条锚点 / 多大比例的身份描述
2. **观察窗**：变更先进 `pending`，N 轮内可撤销，到期才落定

**验收**：一次试图改写 5 条 L1 锚点的请求被限幅；改 1 条的请求进入观察窗，下一轮可撤回。

### M2.3 漂移分级（A7 的替代方案）

A7 当初否掉静态判定线。CT Toolkit 给出另一条路：**线不是开关，是分级**。

```
L1 语义预警（只记录）→ L2 裁判（旁路评估）→ L3 身份机制（拒改 / 回滚）
```

**验收**：连续 N 轮出现同向偏移时，L1 计数触发 L2，但不是每次都升级。

## M3 归档检索

- 分阶段下钻：`所有 → 年 → 月 → 周 → 天 → 时`，任一层命中 ≤3 条则直接给片段
- 用户备注：挂在会话上，与时间检索**并列**运行，不注入上下文
- **来源**：原教旨 G；备注定义见 `05-forgetting-plan.md` 3.2

**验收**：能问"去年三月有什么"，返回月份级列表；问"那条关于缓存的"，能靠备注命中。

## M4 审计成链

现在审计是 SQLite 表，能改能删。但文档里写着"审计是承重墙"。

- 每条审计条目带前一条的哈希（HMAC-SHA256 链）
- 启动时校验链完整性，断链则拒绝对外宣称"可审计"
- **来源**：CT Toolkit 的 provenance chain

**验收**：手工改一条审计记录后，校验能发现。
