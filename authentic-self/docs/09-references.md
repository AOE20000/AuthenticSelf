# 参考工作对照（2026-10-25）

> 目的：确认我们六个模块各自"最接近的已有工作"做到了哪一步，以及**它们共同缺的那一块**是不是我们真正要做的东西。

---

## 0. 一句话结论

**六个模块都有成熟参考，但它们有一个共同的空缺：没有任何一个系统让主 AI 就"记忆/自我该怎么变"发起交涉。**

它们分别是这样绕过去的：

| 做法 | 代表 | 缺什么 |
|---|---|---|
| 主 AI 自己调记忆工具 | MemGPT / Letta 早期 | 慢、且它得理解工具 |
| 记忆由后台代劳，主 AI 完全不管 | Letta sleep-time | 主 AI 无法表达"别想起这个" |
| 只做读写，不做协商 | Mem0 / Dream | 没有"为什么改"的通道 |
| 外部治理平面统一裁决 | Governed Self-Modification | 主 AI 是**被治理对象**，不是交涉方 |
| 结构化外壳硬约束 | BALLERINA / MSCP | 约束是静态的，不可谈 |

**所以 AuthenticSelf 的差异点不在"记忆更好"，而在"主 AI 与基础设施之间有一条低摩擦的交涉通道，且它不知道门后是谁"。** 这条在参考里是空白。

## 1. 总表

| 模块 | 最接近的工作 | 它做到了 | 差距（对我们） |
|---|---|---|---|
| 主 AI 只面对黑盒、记忆自动浮现 | **Generative Agents**（Park et al. 2023） | 记忆流 + 三因子检索（时近/重要/相关）+ 反思写回 | 记忆只进不出；**没有交涉通道**，主 AI 不能要求"别再浮现" |
| 旁路 AI 后台整理记忆 | **Letta sleep-time compute**（0.7.0 / 2025） | 主代理与睡眠代理分离；记忆编辑工具**只给睡眠代理由**；可配不同模型与频率 | 主代理仍要**主动调工具**读写核心记忆；睡眠代理的修改无人复核（除可选的二次评审） |
| 记忆自动抽取与巩固 | **Mem0 v2 + Dream**（2026-08） | 抽取 → ADD-only；Dream 后台做 merge / supersede / synthesize；**不删除，只改状态并指向替代者** | 缺身份层级，缺审批；冲突处理在付费功能里 |
| 分层锚定的人设/自我 | **ID-RAG**（arXiv 2509.25299）、**BALLERINA**（Cognitive Systems Research 2026）、**Multi-Anchor** | 身份设为独立知识图谱并每步检索；"约束性外壳"而非行为微调；身份冗余分布在四类锚点 | 身份是**只读**的：可检索、可约束，但**没有受控的变更流程** |
| 大改强制反思 + 独立审批 | **Governed Self-Modification**（arXiv 2607.12254）、**MSCP** | "agent 提议、外部决定"；三层 SOUL（不可变/稳定/自适应）分级审批；delta-clamp、身份哈希、回滚 | 面向**能力自增强**，不是"自我/人格"；治理平面过于企业化 |
| 累计漂移预算 + 冷却/复位 | **CT Toolkit**（Apache-2.0）、**MSCP** | CT：三层漂移分级 + 影子请求预演 + 冷却生效 + HMAC 溯源链；MSCP：delta-clamp + 身份哈希 + 回滚 | CT 是**外部护栏**、MSCP 是**安全协议**，两者都不含记忆语义，也没有交涉通道 |

## 2. 逐条要点

### 2.1 Generative Agents —— 我们该抄的是"检索三因子"

- 记忆流：append-only、自然语言、带时间戳与最近访问时间。
- 检索分 = 时近（指数衰减 0.99）+ 重要（让模型打 1–10 分）+ 相关（embedding 余弦），三者 min-max 归一后等权相加。
- 反思：当近期记忆的重要性累计过阈值，生成更高层结论**写回记忆流**，且反思还能被反思。

**可借**：我们的 `recall()` 现在只用二元组重叠（等于只有"相关"一维）。**缺"重要"与"时近"**。`salience` 字段已经存在但没进打分——这是最便宜的一处改进。

**差异**：它是模拟，不是对话；记忆只进不出，主 AI 从不要求"忘掉"。

### 2.2 Letta sleep-time —— 我们的"维护旁路"有工业先例

- 主代理与会睡觉的代理分离，**核心记忆的编辑工具只挂在睡眠代理上**。
- 可配不同模型（睡眠代理用更强更慢的）、不同频率。
- 修改是 "anytime" 的：主代理随时可读，不必等它算完。
- 后来的产品形态还加了 `/remember`（显式教）、`/sleeptime`（配置）、以及"应用前让代理二次评审"的选项。

**可借**：①"编辑权只给旁路、主 AI 不给"这条我们已经定了（B1/B2），它是佐证；②"anytime 修改"的并发模型——我们的 SQLite 直接读写天然满足；③二次评审选项，对应我们的 R6。

**差异**：主代理仍要**自己调工具**去 recall；睡眠代理的改动**没有独立审批**（只有可选自审）。

### 2.3 Mem0 + Dream —— "遗忘不是删除"的工业实现

Dream 做三件事，且**没有任何删除**：

| 操作 | 语义 |
|---|---|
| Merge | 新记忆覆盖旧记忆的全部信息时，旧的标 merged 并指向新的 |
| Supersede | 新旧冲突时，旧的标 superseded 并指向新的（默认仍可检索，`latest_only` 才滤掉） |
| Synthesize | 后台按相似度分组，多个独立观察支持同一结论时才写一条 pattern，并链回全部证据 |

且明确：**写入路径要快，所以只做哈希去重；冲突处理搬到后台**。这正是我们"维护旁路 10 轮一次"的分工逻辑。

**可借**：我们的 `suppress()` 只有"抑制"一种状态，**缺 merge / supersede 两个状态及其指针**。这三种状态合起来才是完整的遗忘语义。

**差异**：Mem0 的 scope 是 `user_id/agent_id/run_id`，没有"身份层级"；也没有人审批。

### 2.4 ID-RAG / BALLERINA / Multi-Anchor —— 分层锚定的三种做法

- **ID-RAG**：身份 = 独立知识图谱（Chronicle：values / beliefs / traits），与情景记忆**分开存**；每次决策前生成一个"身份查询"去图里取三元组，作为"时间锚点"注入工作记忆。实测身份召回更高、收敛更快（小模型上收敛时间降 58%）。
- **BALLERINA**：不微调、不加记忆，而是给一个"结构化认知外壳"，用**约束性容纳**稳定解释空间、过滤辩护性推理；对抗提示下角色漂移事件减少 87%。
- **Multi-Anchor**：身份不能只存一处。至少四类锚点冗余：声明式（SOUL.md 类）、情景式、行为式、关系式；任一损坏其余兜底。

**可借**：ID-RAG 证实了"身份与记忆分家"是对的（我们 L0–L4 已经这么分）；Multi-Anchor 的"冗余"提醒：**L0 编译进代码 + L1 锚点 + 行为样本**三者应该互为备份，而不是只有一份。

**差异**：三者的身份都是**只读**的——可检索、可约束，但没有"谁可以改、怎么改、改错了怎么办"。

### 2.5 Governed Self-Modification / MSCP —— 变更门控的最强参考

**Governed Self-Modification（arXiv 2607.12254）** 的核心就一句：**agent 提议，外部系统决定。**

- 治理平面：默认拒绝的策略引擎、资源治理、凭据代理、**带隐藏任务的独立评测器**、防篡改审计日志、回滚控制器、带外关机通道——且运行在**与代理不同的管理身份**下。
- 准入谓词 `Accept(A, A′)` 要求同时满足：留出集上真有提升、安全阈值、风险上限、**权限增量已批准**、来源完整、**可回滚**。
- 三层 SOUL.md：不可变 / 稳定 / 自适应，分别对应"人类批准 / 同行评审 / 代理可自改但监控"。

**MSCP** 更偏工程实现，它的九层安全栈里有几条正好是我们的语言：

| MSCP 机制 | 对应我们的 |
|---|---|
| Layer 0 不可变伦理不变量（不依赖 LLM） | L0 编译进代码 |
| Layer 1 核心价值锁定（SHA-256 校验） | 锚点完整性校验 |
| Layer 2 delta-clamped 自更新（每步最大 Δ） | **变更幅度预算**（我们只写了"冷却/回滚"，没写"每次改多少"） |
| Layer 3 元升级守卫（越阈值回滚） | D15 漂移处置 |
| Layer 4 预测门控（先预测再执行） | R6 审批（但它是数值预测，我们是语义判断） |

**差异**：两者都面向"能力/安全"，不是"人格连续性"；且治理平面极其沉重，不适合一个人的系统。

### 2.6 CT Toolkit（Theseus-Guard/ct-toolkit）—— 漂移审计做得最实的一个

Apache-2.0，Python，可直接读源码。它的定位一句话：**"Identity Continuity Guardrails for Agentic Systems"**——防止 Agent 在长时运行与多级嵌套中偏离最初的宪法。

它把"跑偏"这个行为学问题变成三个可操作的东西：

| 机制 | 它怎么做的 | 对我们意味着什么 |
|---|---|---|
| **三层漂移分级** | `OK / L1_WARNING（语义预警）/ L2_JUDGE（裁判评估）/ L3_ICM（身份连续性机制）`，并给出 divergence score（均值/峰值） | 我们一直说"不设静态判定线"（A7）。它反过来：**设线，但分三层**，越界才升级处置。这是 A7 的一个可行替代——线不是开关，是**分级** |
| **Staged Approval（冷却生效）** | 高风险的内核更新先走**影子请求**在沙箱里预演，冷却期后才真正生效（CLI 里能看到剩余秒数） | 我们只有"事后回滚"。它是**事前预演 + 观察窗**——比 delta-clamp 更完整 |
| **宪法内核 + 分布式传播** | 身份锚点公理化，用 HMAC-SHA256 签名的 HTTP 头跨服务传播 | 我们 L1 锚点的完整性校验，它给了工业形态 |
| **被动压缩检测** | 专门检测**供应商侧静默压缩历史**导致的漂移 | 直接对应我们的隐患：pi 自己也会压缩，我们只能在 `session_compact` 里事后知道 |
| **可验证溯源链** | HMAC 签名的不可变哈希链（SQLite/PG），带分页验证与 OTel | 我们说"审计是承重墙"。它的审计是**防篡改链**，不是一张表——这才配叫墙 |
| **自主纠偏** | L2→L1 反馈环，在响应到达用户前重试并纠正 | 我们的 R4 剔除是同类动作，但它检的是"漂移"不是"污染" |

还有几处工程细节值得记：规则冲突检测做 **Unicode 规范化 + 整词匹配**（防子串绕过）；L2 裁判**不评估**用户请求里的 Jinja2 表达式（防模板注入）；下载内核/身份/探针文件必须匹配随包的 SHA-256 清单，否则**拒绝写入**（fail-closed 默认开）。

**差异**：它管的是"Agent 别偏离宪法"，不管"记忆怎么组织"；也没有"主 AI 与基础设施交涉"这一层——它是**外部护栏**，我们是**内部基础设施**。但它的三层分级、影子预演、哈希链，正好补上我们最薄的三处。

## 3. 对我们设计的三个直接修正

这轮对照下来，有三处不是"补参考"，而是**我们的设计确实缺**：

### 修正 1：检索只用了一维

`recall()` 目前只算二元组重叠（相关）。Generative Agents 的结论是**三因子缺一不可**：只看相关会永远返回同几条，只看时近会忘掉重要的。

`salience` 字段已经在库里躺着没被用。最低成本的修法：

```
score = w_r·recency(指数衰减) + w_s·salience + w_rel·重叠度
```

### 修正 2：遗忘状态只有一种

我们的 `state` 只有 `active / suppressed`。Mem0 Dream 证明工业上需要三种，且**都要指向替代者**：

```
active ──merge──→ merged（指向新条目，默认不检索）
       └supersede→ superseded（指向新条目，默认仍可检索）
       └suppress→ suppressed（无替代，人为屏蔽）
```

这比"只有抑制"更贴近原教旨那句"遗忘不是删除"——因为 merge/supersede **保留了"它被什么取代了"这条链**。

### 修正 3：缺"每次改多少"的预算，与"改完先观察"的窗口

我们写了 D15（漂移处置：不自动复位、最多拒改或回滚），但缺两样：

1. **单次变更的幅度上限**（MSCP 的 delta-clamp）——不是"能不能改"，而是"一次最多改多少"。
2. **生效前的观察窗**（CT Toolkit 的 staged approval）——改动先进沙箱预演，冷却期后才真正落地。

两样合起来才治得住漂移：delta-clamp 限制**步子大小**，staged approval 给它一个**可以反悔的窗口**。只有事后回滚的话，"要么没变、要么面目全非"这个二象性永远存在。

### 修正 4：审计不该只是一张表

我们说"审计是承重墙"，但我们的审计是 SQLite 里的一张表——能改、能删、能补。
CT Toolkit 用的是 **HMAC 签名的不可变哈希链**，并且 fail-closed：校验不过就拒绝写入。

如果这句话是认真的，审计就该是**链**而不是表。这条不影响近期功能，但影响"这套系统的承诺有多硬"。
