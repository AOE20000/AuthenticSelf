## 2. 六项 dsh 专属妥协

### T1 注入以 `user` 消息落地（措辞靠 prompt 补救）

- **现状**：`01 §5.1`、`as-inject` 用 `createUserMessage` 把记忆塞成用户发言，靠"这不是用户的新请求"这句话压住模型。
- **原教旨**：只说"无需工具调用的记忆注入"，没规定载体。但载体错了的后果很实在——实测两次，模型把记忆当成用户的新问题去回答。
- **判断**：这是 dsh 的**消息角色限制**逼出来的补丁，不是设计选择。
- **pi 上**：steering 是原生的"中途插话"，语义上更像"系统在提示"而不是"用户又说了一句"。
- **建议**：改用 steering；若 pi 的 steering 仍以 user 角色落地，则保留措辞补丁但记录为已知缺陷。

### T2 多轮思考靠"延长 turn"（依赖 dsh 循环内部行为）

- **现状**：`01 §5.4` 用 `agent/turn-stopping` + `inject()` 让 turn 多走一步；文档里连 agent.ts 的行号都记了。
- **原教旨**：未直接要求多轮，但"想到什么就载入什么"隐含"想起来之后还要继续想"。
- **判断**：效果等价，但实现是**借宿主内部的巧合**，换基座即失效。
- **pi 上**：原生循环 + steering，不需要这个技巧。
- **建议**：整套丢弃，直接挂在 pi 的循环钩子上。

### T3 剔除靠消息投影（`registerMessageProjection`）

- **现状**：`02 B6-a`、`01 §8` 用 dsh 的纯投影改"模型所见"并保住日志真相。
- **原教旨**：未提剔除。这是工程需要，不是原文要求。
- **pi 上**：没有投影机制 → 要么自建"消息改写 + 重放"，要么放弃"日志留真"这条。
- **建议**：若 pi 的消息数组可被改写，直接改写 + 记录 diff；否则降级为"只做前缀抑制"。

### T4 profile 隔离（D20）

- **现状**：`01 D20`、`02 B7`，数据挂在 `$DSH_HOME/profiles/<name>/`。
- **原教旨**：无"profile"概念。
- **判断**：这是 dsh 的部署单位，被我们借来当"人格实例"的边界。
- **pi 上**：没有这个单位，需要自建目录约定（一个人格一个数据根）。
- **建议**：保留语义，改名"人格实例"，不叫 profile。

### T5 子代理（B9）

- **现状**：`02 B9` 依赖 dsh 的 `ctx.subagents`。
- **原教旨**：明确要求"提供不使用 AuthenticSelf 的子代理"。
- **pi 上**：`pi-coding-agent` 自带 read/write/edit/bash 四工具，可作为"无 AS 子代理"的现成底子。
- **建议**：用 pi-coding-agent 做子代理的宿主，而不是自己写一遍工具层。

### T6 bundle / cordis 插件体系

- **现状**：`as-core` / `as-store` / `as-inject` 三个 Cordis 插件 + `cordis.patch.yml` 组合层。
- **原教旨**：无关。
- **pi 上**：没有 Cordis。要么沿用 Cordis 当作独立 DI 容器（可行，vendor 还在），要么改成普通模块 + 显式装配。
- **建议**：**保留 Cordis**。vendor/cordis 已随前端保留，且服务注入/生命周期对"旁路与代码服务"的形态很合身。这是少数值得带走的 dsh 遗产。

## 3. 与原教旨的冲突（四处，全部已裁决）

### C1 主 AI 到底知不知道"黑盒"存在 —— 已裁定 A

| | 原文 | 旧裁定 |
|---|---|---|
| 位置 | 原教旨 D + E | `02 A5` |
| 说法 | "**提供黑盒的交涉通道**…"；"…**最后向黑盒发起请求**，由旁路 ai 审批" | "主 AI 不应知道审批机制存在" |

**裁定：A。知道有门，不知门后。** 它可以声明/提请一件事，但不知道谁审、按什么标准审、被拒的结构。`change_intent` 的定位从"申请"改为"声明"。

已写入 `02-isolation.md` 的 **A10 / 0.2**，B2 的"不应知道存在"作废。C2 是同一问题的另一面，一并覆盖。

### C2 "黑盒"的"黑"指什么 —— 随 C1 解决

原文的"黑盒"是**机制不可见**（无需理解它怎么工作），不是**存在不可知**。我们沿 B1 推到了"存在也不告知"，超出原文。已按 A 收敛。

### C3 "必须先重复思考" vs 我们的表单式反思 —— 已裁定

**裁定：这是自问自答流程，不设迭代闸门。**

- 「重复思考」发生在**主 AI 自己内部**：在系统提示词里告知它「大改之前先自问为什么、会导致什么、不改会怎样」，它自己想清楚再提交。
- 旁路**只处理一次**：拿到结果评审一次，不追问、不要求补第二轮。
- 所以 `ChangeIntent` 的十字段保持不变，改动只在**系统提示词**，不在流程结构。

好处是零额外延迟；代价是"自问"的质量取决于提示词与模型自觉，代码侧无法验证"它真的想过两遍"。

### C4 "无需理解" vs 要求它懂 `kind` 枚举 —— 已裁定

**裁定：单一触发 + 自然语言。**

`memory_intent` 收敛成一个入口，只收**自然语言 + 可选的目标指针**，`kind` 由旁路解析：

```
memory_intent({ say: "把上周那个 Redis 的结论忘掉", target?: "Redis 缓存选型" })
```

主 AI 不需要知道有 forget / revise / remind / link / unlink 这五类——那是旁路的内部枚举。这与原文"简单易懂**甚至无需理解**"一致，也让"想什么时候想起一件事""把两件事联系起来"这类表达不再要求它挑对枚举值。

## 4. 原教旨要求、但我们漏掉的两项（均已按新口径解决）

### M1 归档的"备注" —— 改为用户注脚

原教旨 G：「只能通过**索引、备注**、强制分阶段搜索」。

我们实现了分阶段（`所有→年→月→周→天→时`，早停阈值 ≤3），但**"备注"完全没有设计**。`recall_scope` 只有路径和摘要，没有"人给这段时间写一句话"的位置。

后果：归档退化成一个只能按时间翻的储物柜，丢掉"人记得某段时间发生过什么"这一层——那恰恰是"模仿人"的核心。

**解决**：备注不是旁路自动生成的小结（那与摘要同义反复），而是**用户为对话添加的注脚**——挂在会话上、由人写、与分阶段时间检索**并列**运行、不注入上下文。详见 `05-forgetting-plan.md` 的 3.2。

### M2 "复杂请求强制设计计划"

原教旨 F：「…因此需要参考人的遗忘机制、遗忘补救方案、**复杂请求强制设计计划**和提供不使用 AuthenticSelf 的子代理。」

后两项我们做了（遗忘补救、子代理），但"复杂请求强制设计计划"在文档里**一个字都没有**。

这是明确列在需求里的东西，漏了。

**解决**：它不是工程问题。LLM 本来就会对自己能判断出的复杂请求先展开计划，**只需在系统提示词里告知**。因此不建计划板、不做复杂度判定、不做"未登记就单步降级"；连带取消 R1（计划板回放），补救变为 R2–R5。代价与两个补丁见 `05-forgetting-plan.md` 的 3.1。

## 5. pi 上没有、必须自建的（工作量，不是设计问题）

1. **Web BFF**：保留下来的 dsh 前端要一个后端协议。pi 不带 Web 层，这层要自己写——这是"保留前端"的真实代价。
2. **持久化**：`pi-agent-core` 只有内存 messages；会话落盘、断点恢复要自建（或复用 `pi-durable`）。
3. **上下文压缩的边界**：pi 内置 compaction，我们也有"遗忘"。必须定清楚谁管什么，否则两套裁剪会互相打架。

## 7. 遗忘：一次被判为错的收敛建议（保留原样，留作记录）

> **本节结论已被推翻，不要按它执行。**
> 我当时的判断是"五件套虚胖，应砍到压缩 + 抑制"。用户指出：原教旨的"不溢出"是靠**对旧上下文逐项调整**实现的——重要的不动、不重要的只留摘要/索引。要做到"逐项"，就必须有分区、有降权、有索引化、有补救通道。
> 所以正确的结论是**粒度更细**，不是机制更少。实际方案见 `05-forgetting-plan.md`。

以下是当时的推理，保留是因为它记下了"为什么会读窄"：

先把原文的两句话并排放：

> F：「对于遗忘机制。AuthenticSelf 需要保证的**只有**单次超长对话上下文不溢出，因此需要参考人的遗忘机制、遗忘补救方案……」
> D：「想**删掉某个记忆**、想把某段记忆**改成什么样子**、想**什么时候想起**一件事情、想将多个事情**联系起来**……」

**误读点**：我把"只有……不溢出"理解成"不溢出 = 截断"，于是把 F 读成"遗忘的天花板很低"。实际上"不溢出"是**结果**，"逐项调整"是**手段**，而手段本身就需要一整套操作集。
