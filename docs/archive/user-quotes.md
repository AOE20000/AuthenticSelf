## 一、项目原始构思（逐字全文）

出自 [`../source/AuthenticSelf.txt`](../source/AuthenticSelf.txt) 第 1–18 行（该文件第 19–909 行为早期 AI 基于以下原话展开的初版衍生文档，规范与原始构思冲突时以原始构思为准）：

> 以下内容的灵感源自对“潜意识”这一存在的思考，最终目的是“模仿人”：
>
> 其实神经网络已经非常像人类了，但他只是个预测模型，尽管已经非常强大，但他需要独自处理的事务太多太多了。
>
> 我们可以给予其想到什么就载入什么的而无需工具调用的记忆注入、旁路自动处理记忆的ai、以及大量类似的，仿照人脑基础设施。
>
> 多变的信息处理靠旁路ai，不多变的靠代码服务稳定处理。对主ai只暴露简单易懂甚至无需理解但“天然”存在的功能。也就是这一套基础设施在常规情况下都是“黑盒”。
>
> 还需要提供黑盒的交涉通道，比如想删掉某个记忆、想把某段记忆改成什么样子、想什么时候想起一件事情、想将多个事情联系起来并在下次想起时关联注入。
>
> 还有强鲁棒性，任何大修改大转向时必须先重复思考为什么、会导致什么等，最后向黑盒发起请求，由旁路ai审批。并参考人也会被忽悠，但可清醒这一套心理学逻辑增强这方面的鲁棒性。最终目的是人设、自我等高具有高可靠性。（此条方案是上一版为：旁路ai在每天第一次启动前更新prompt）
>
> （虽然灵感来自潜意识，但对潜意识这一存在本身却没想到什么合适的对应，但他一定是有存在意义的。）
>
> 对于遗忘机制。AuthenticSelf需要保证的只有单次超长对话上下文不溢出，因此需要参考人的遗忘机制、遗忘补救方案、复杂请求强制设计计划和提供不使用AuthenticSelf的子代理。
>
> 还可以提供上下文永久归档功能，只能通过索引、备注、强制分阶段搜索，如对“所有”归档搜索时返回“哪几年有结果”，直接对“所有/年”内搜索时返回“哪些月有结果”，直接对“所有/年/月/周/天”搜索时返回“哪个时间有结果”，直接对“所有/年/月/周/天/时”搜索时才给出具体片段。如果搜索的阶段中片段过少，则直接返回具体片段，受此机制影响的阶段为全部“所有、年、月、周、天、时”。

## 二、立项、架构与隔离裁定（2026-10-24 ~ 10-25）

### 2.1 立项方式与「潜意识」边界
- **v0 方案被否决**：判定初版成品骨架**「不符合预期」**，要求清理后先逐条对齐需求与边界，再写文档和代码（偏好：**不要先给成品架构就落地骨架**）。
- **明确撤回「潜意识」实体化**：禁止把“潜意识”直接对应为旁路 AI、记忆基础设施或内感受黑盒；“潜意识”仅作为灵感与开放设计透镜存在，不进入组件命名、因果解释与评估指标。

### 2.2 核心架构订正（20 项决策见 [`../01-architecture.md`](../01-architecture.md) §2）
- **D6 / D10 订正**：长短分类只决定**注入路径**，不是存储分家；单一 `MemoryEntry` 表，`span` 由代码服务派生（`short` 直接注入，`long` 交旁路裁决）。“尽量别塞长文本”是建议而非禁令。
- **双向注入补正**：注入机制是双向的（上行：记忆 → 上下文；下行：上下文 → 记忆），共用同一套通道、表、来源标注与审计；立下防自毁规则——**“写进去”本身绝不提升权重**。
- **延迟与容忍度**：明确表达对延迟容忍度高——**「慢点是必须接受的，不可接受就不要用 AuthenticSelf」**；但不能接受系统错误导致的挂死，因此超时用 idle timeout 且写入须可回滚。

### 2.3 黑盒边界与记忆落盘（B1-a）
- **选真边界**：认定黑盒必须是**边界**而非约定。
- **曾提问探索纯内存**：**「不能纯内存提取后注入吗，不暴露文件位置」**（随后短暂试验了纯内存方案）。
- **纠正回必须落盘**：随后明确澄清记忆库必须落盘——不能把记忆退化成会话级缓存，形态要求**「稳定、容量大、不易被直接读取」**（最终采用 `node:sqlite` 二进制页格式单文件），主 AI 只看得见会话上下文与注入结果。

### 2.4 一句话回应内的多轮注入
- 澄清「下一轮」发生在**同一句回应的内部**，标准时序为：**「思考 1 → 旁路 1（注入原神）→ 思考 2 → 旁路 2（原神已注入，跳过）→ 正式输出」**。

### 2.5 隔离裁定（A1–A10，详见 [`../02-isolation.md`](../02-isolation.md) §0）
- **A1**：审批者不能看最新用户消息（主 AI 的思考里已包含相关信息）。
- **A2**：R4 剔除自动执行，不挂起等人工；安全性改由“极低触发率 + 可回滚 + 全审计”承担。
- **A3**：跨会话记忆共享，仅按 profile 隔离。
- **A4**：导入/导出只允许**整包**（整个配置或整个上下文），导入内容打标**「此会话的上下文仅供参考」**且永不自动升格。
- **A5 / A10（修正 B2）**：
  - A5 指出审批者常态不是“卡死一切的闸门”，而是把主 AI 的口语**标准化成可执行命令**；
  - 换基座审计时补充裁定 A10：**「知道有门，不知门后」**——主 AI 知道有一个可“提请”的出口（声明而非恳求），但不知道谁在审、按什么标准审、被拒的具体结构。
- **A6**：人可直接读归档——归档就是**一个会话的上下文本身**，归档库就是**所有会话**；分阶段下钻只约束 AI。
- **A7**：**不设静态判定线**，旁路在帮助执行的同一遍里区分风险；判断归模型，后果映射归代码，三条硬不变量不可谈。
- **A8**：「读过 ≠ 记住」——以发送视图净化实现剔除（存档不动）。
- **A9**：采用 VS Code「受限模式」语义——**信任是会话属性，按会话切换**；不受信任会话的所有写入进入 `pending_write` 队列待人批或无视。

### 2.6 仓库独立化与换基座到 Pi（2026-10-24 ~ 10-25）
- **停止 dsh 后端开发**：判断继续在 dsh 后端架构里改**「有些怪，有做屎山的味道」**，决定仓库独立（仅保留 AS 与前端评估），随后决定改用 **`pi`**（`pi-ai` / `pi-agent-core` / `pi-coding-agent`）作基座，让 AuthenticSelf 以 **Pi 扩展**形态运行（可挂在 `pi` CLI、Aether 或其他 Pi 发行版上）。
- **封存 dsh 前端**：在验证 Pi 扩展 API 完备后，对保留的 dsh 前端评价**「食之无味弃之可惜」**，决定封存前端（留存于历史 tag），专注做无 UI、无构建的 Pi 扩展。
- **对原教旨冲突的四项裁决**（记录于 [`pi-migration-audit.md`](pi-migration-audit.md) §6）：
  - C1/C2：知道有门、不知门后（即 A10）；
  - C3：「必须先重复思考」是主 AI 内部的自问自答（在系统提示词告知），旁路只审一次；
  - C4：`memory`（原 `memory_intent`）收敛为单一触发 + 自然语言（`{ say, target? }`），`kind` 由旁路解析，不要求主 AI 理解枚举；
  - M1 备注、M2 强制计划初判“之后再说”，随后于遗忘专题补定。

## 三、机制纠偏与细化定案（2026-10-25 ~ 10-27）

- **遗忘语义纠偏（推翻“砍到压缩+抑制”建议）**：指出原教旨的「不溢出」不是靠直接截断，而是靠**对旧上下文逐项调整**（重要的不动，不重要的只留摘要/索引），因此五区与七种操作（含降权、脱敏、隔离）必须保留，粒度要细而非砍机制。
- **遗忘机制五点裁定**：① 关掉 pi 内置 compaction，全部走五区；② 输出预留为**可被用户修改的固定值**（默认 8192）；③ 逐项调整只在到达预算阈值时统一执行，平时只称重；④ 计划板延后；⑤ 不可移出区由维护旁路每 ~10 轮批量打标 + 压缩时刻未标尾巴进 `unreviewed` 当场判。
- **`unreviewed` 临时标记与双写**：明确 `unreviewed` **只在未标记条目需要开始遗忘那一刻临时打上，这趟处理完就摘掉**，不落库、不累积；并提出**用户明确要求记住的内容会写进记忆库**（上下文 `pinned` 只是省一次 R2/R3 取回，不是唯一副本）。
- **取消工程计划板（F6）**：判断**「LLM 本来就会对自己能判断出的复杂请求先展开计划」**，只需在系统提示词中告知，不必重造计划板与单步降级工程（后于 P15 落地为轻量 `plan` 摘要区 + `STEP <n>` 进度追踪）。
- **归档与备注指正**：
  - 指正**「备注是对一个会话的，不是对会话里某条对话的」**（`note` 挂在 `session_file` 上）；
  - 澄清**归档就是一个会话的上下文本身，归档库就是所有会话**；
  - 指正**「归档查询只有搜索，没有拒绝」**（推翻第一版 `read` 拒绝门，重写为六层粒度钳制）。
- **按轮压缩原则**：明确**「全局视野、局部写回」**（允许旁路一次看多轮，写回必须保留一轮最小单元、不可合并轮次；保护轮只读可见）；随后纠正**「不要用正则识别"别压"这类措辞」**，打标记统一归维护旁路。
- **标签树早版规则与「叶=槽」**：
  - 初期定下：父级禁止自动创建、不限层数、不限总数、单条 ≤7 字；
  - 纠正“识别同一件事”的解法：指出第一层识别**天然由标签树解决**，同一叶子下挂的就是同一槽的版本（路径本身就是身份），由此确立**「叶=槽」**。
- **统一旁路与移除「直接注入」**：要求把三条注入路径合为一条，随后定案**移除「直接注入」**——召回只产候选，记忆旁路是唯一闸门。
- **「我」的指代纠偏**：纠正「记忆不一定是用户的记录」，促成候选清单带 `origin` 分层，按来源决定人称指代。
- **工作规则（2026-10-27 明确要求）**：因连续三次未先读完文档再写代码（指代、归档、门控），明确立下硬规则：**「动手前先读完相关文档，做完后再对一遍文档」**。
- **D2 修订**：不砍 `archive`，将判定标准收紧为：**「原语 = 能改变记忆或身份的工具。只读工具不计入。」**
- **审批者定位三次纠正**：先质疑 `change_intent`「有点不符」（未做标准化器而做成一律待批），后第三次纠正：**「任务」指给审批者的系统提示词，而不是主 AI 的请求**——审批者本身是 AI，不预设“通常通过/通常拒绝”，只要任务书写清楚即可判出好坏。
- **去掉 `recency` 与转存判断时机**：判断注入改为旁路挑且每条带日期后，`recency` 衰减是重复计算，应去掉；裁定 `recommendDoc` 挪到**写入时**处理，因为“是否该写成文档”是内容自身属性，不随某次提问改变。
- **阶段制与「记忆旁路」定名**：提议强制顺序的阶段制（先读取与判用、标记完成再开放沉淀），之后定案合并后统称**记忆旁路**，澄清组件名为**记忆旁路（阻塞）**与**记忆旁路（非阻塞）**，检索/判用/沉淀/预取为各自内部的阶段名；并提议用代码状态机强制相位门。
