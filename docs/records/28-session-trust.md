## 一、两张表与三状态语义

```sql
session_trust(session_file PK, state, switched_by, switched_at)
pending_write(id PK, session_file, text, origin, tag_path, salience,
              reason, state, created, settled_at)
```

`state` 的取值是 `trusted | untrusted`，**只有两态**。`02` 表里的第三行
「积压待确认」描述的是这个会话在 `pending_write` 里有行，不是开关的第三个值——
把它做成第三态会立刻出现"积压批完了算什么状态"这种没有答案的问题。

| `02` 表里的状态 | 实现 |
|---|---|
| 受信任：上行正常、下行正常入库 | `getTrust() === 'trusted'`（**没有记录也用这一行**） |
| 不受信任：上行正常、下行一律入队 | `getTrust() === 'untrusted'` → `enqueueWrite()`，不进 `memory_entry` |
| 积压待确认：人批准后才入库 | `pending_write.state = 'pending'` 的行；`adoptWrite()` 才真正 `add()` |
| 谁能切：默认给本机新建会话 / 其余仅人 | 代码里**只有** `/as-untrust` `/as-trust` 两个命令写 `session_trust`；模型无路径 |

`pending_write` 的 `state` 是 `pending | adopted | ignored`。已处置的行**不删**——
它是"这条被批准过 / 被无视过"的凭据，删了就无法解释积压为什么少了。

## 二、为什么默认受信任

`02` B7-a 的表格把「受信任」写成"默认给本机新建会话"，`01` §4.3 的表格同样把
「受信任（本机新建）」标为"默认"。这条不是疏忽，它是可用性的前提：

- 若默认不信任，**第一次用就写不进库**——而人此时还没有任何理由去开这个开关，
  也不知道要开。记忆系统第一次运行就静默降级成"只读"，等于上线即坏。
- 污染入口只有两类：**导入**与**外来会话**。这两条路径现在都还不存在
  （没有导入命令、没有外部来源建会话的入口），所以"默认受信任"在当下不放过任何
  真实风险，只是把开关放在人需要它之前的位置。

**张力必须留痕**：A9 的字面是"默认不信任，按会话手动切到信任"，`01` §4.3 的正文
也这么写。它讲的是**导入/外来会话**的起点；`02` B7-a 的表讲的是**本机新建会话**的
默认。我们按后者实现，因为前者还没有落点。**导入路径一旦落地，初始态必须按来源判定**
（`imported` → `untrusted`），这条不能忘——否则默认值会变成真的漏。

**与 `01` §13 fail-closed 的关系**（容易被误读成违反）：那一行说的是"**读不出**
`session_trust`"时按不受信任处理。实现里 `getTrust()` 区分两种情况：

- **表里没有这一行** = 新会话的正常态 → trusted（本节的理由）；
- **读表本身失败**（库损坏、连接断了）→ `prepare/get` 直接抛错，不会静默返回 trusted。

也就是说 fail-closed 没有被放弃，只是它守的是"故障"，不是"空表"。

## 三、为什么不追认积压（`02` §5.4-1）

`setTrust(file, 'trusted')` **不动任何 `pending` 行**，代码里就没有这条路径。
理由是语义上的：`/as-trust` 回答的是"从此以后这个会话可以写"，不是"过去那些也想写的
现在算数"。后者是一次**批量采纳**，必须由人显式做。

现状：批量采纳**只做了逐条**（`/as-adopt <id>`），`02` 提到的"全部批准"按钮/命令
**还没提供**。这是有意的保守——批量采纳是人的决定，宁可先让人一条条看。

## 四、可读不可写的落地边界

上行完全不受影响：召回、注入、锚点、计划、归档、备注照旧（`getTrust` 只出现在写入路径）。
下行收敛成**一个函数**：

```ts
writeMemory(sessionFile, text, { origin, tagPath, salience, reason }): string | undefined
```

三处写入点都改走它（形态最小改动，`store.add` 的其它调用没动）：

| 写入点 | 位置 |
|---|---|
| 收尾相沉淀（`REMEMBER`） | `pi/src/index.ts` `runWrapup` |
| 维护旁路补记（`REMEMBER`） | `pi/src/index.ts` `runMaintenance` |
| 交涉通道 `REVISE` | `pi/src/index.ts` `handleMemoryIntent` |

`store.add` 的其余调用（`AS_SEED` 播种）保持原样；**锚点改动不进信任闸**——
它走的是审批链（`addChange` / `judgeChange` / `applyChange`），信任管的是"记忆写入"。

维护旁路另有三类动作改的是**共享结构**，不信任时整段跳过：

- `relations`（`merge` / `supersede`）——改的是别人的条目状态；
- `tags`（`ensureTag`）——冒出来的标签会被所有会话看见；
- `tagOps`（`mergeTag` / `pruneTag`）——会把已有记忆挪位置。

不跳过它们，"不受信任"就只挡住了新增，挡不住改写存量。

**明确放行的**（按 `02` §5.4-2 与"权重不算内容写入"）：

- `REDACT` / `addRedaction` / `suppressDerived`：剔除是安全动作，不受信任等级影响；
- `touch()` / `decay()`：改的是权重，不是正文与状态；
- `markTurn()` / `savePlan()`：压缩标记与计划区是会话自己的上下文产物，不进共享记忆。

## 五、信任开关只在人手上

`pi.registerCommand` 五个命令，全部只在人侧可用：

| 命令 | 行为 | 审计 |
|---|---|---|
| `/as-untrust` | 当前会话 → 不受信任；回执"此后本会话的写入会积压，等你看" | `as/trust {session, state:'untrusted'}` |
| `/as-trust` | 当前会话 → 受信任；回执**必须**写"积压不会自动批准" | `as/trust {session, state:'trusted'}` |
| `/as-writes` | 列当前会话的 `pending`（`id` / 来源 / 前 40 字）；空则"无积压。" | 无（只读） |
| `/as-adopt <id>` | 逐条批准 → 此时才 `add()` 进库 | `as/adopt {id, entry}` |
| `/as-dismiss <id>` | 逐条无视 → 标 `ignored`，不落库 | `as/dismiss {id}` |

主 AI 侧不新增任何工具或字段：`memory` 工具的五类动作不含信任，`writeMemory` 也不接受
"以谁的身份写"。回执措辞不假设有 UI（`pi -p` 里命令会被当普通文本，这是已知限制），
也不提"阈值/审批/积压数量"，只陈述动作结果——A9 的"不能感知阈值"落在措辞上就是这样。

**写入审计不记正文**：`as/pending_write` 只带 `{id, origin, reason}`。审计链不该成为
积压正文的第二份副本——否则"没进记忆库"就只是换了个地方进。

**审计怎么不丢**：收尾相是非阻塞的（`agent_end` 里起 promise），它攒的 `as/pending_write`
与 `as/wrapup` 要等下一轮 `agent_before_settle` 才被消费；`session_shutdown` 里在关库前
把剩下的 `state.pendingAudit` 直接 `chainAudit()` 一遍。宁可只有链、没有会话副本，也不整条丢。

## 八、当时残留与后续演变

1. **批量采纳**：写作时只有逐条 `/as-adopt`；**后续已在记录 32 补齐 `/as-adopt-all` 与 `/as-dismiss-all`**。
2. **积压无界增长**：写作时未做上限；**后续已在记录 32 补齐 `AS_PENDING_MAX`（默认 50，超限丢弃新写入并记 `as/pending_overflow`）**。
3. **导入路径不存在**，所以"按来源决定初始信任"没有落点；导入落地时必须同时改默认值逻辑。
4. `/as-adopt` 接受任意会话的队列 id（人侧命令，不按当前会话限制）；`/as-writes` 只看当前会话。
5. `REVISE` 的新文本下限从"非空"收紧到 **4 字**，与 `REMEMBER` 的解析下限一致——
   否则不受信任时 1–3 字的修正会被队列下限挡掉，而回执已经说"记下了"。
6. `pi -p` 里 `/as-*` 会被当普通文本（平台限制）。
