## 实现

**预筛（不调模型）** —— `plan.ts` 的 `looksComplex`：

```
长度 < 40 字            → 不复杂（直接返回）
≥ 2 个多步骤标记         → 交给旁路判断
标记：分几步 / 步骤 / 流程 / 方案 / 计划 / 先后 / 再 / 接着 / 评估 / 迁移 / 重构 / 实现
```

阈值定 40 字而不是原计划的 120 字：中文一句话能装下很多意图，**45 字的迁移需求曾被 120 字阈值误判成短请求**。

**立计划** —— 阻塞相里**单独一次旁路调用**（不并进注入决策那次）：

```
PLAN <一句话目标> || <步骤1>；<步骤2>；<步骤3>
OPEN <开放问题，没有就省略>
```

理由：实测**没有候选记忆时，注入旁路会直接返回「（无输出）」**——计划与"有没有记忆可注入"无关，塞在一起会互相牵连、一起丢。

**存储** —— `plan` 表，一会话一份（`session_file` 为主键，换计划覆盖旧的，历史留在审计里）：

| 列 | 含义 |
|---|---|
| `goal` | 一句话目标 |
| `steps` | JSON 数组，2–5 条可验证的步骤 |
| `open_q` | 开放问题 |
| `state` | `active` / … |
| `created` / `updated` | 时间戳 |

`store` 侧：`savePlan` / `getPlan` / `completeStep`。

**注入** —— `withPlan` 在 `context` 里把计划摘要前置到视图：

```
【当前计划】（1/4 步）
目标：…
  1. ✓ 已做的那步
  2. 待做的那步
开放问题：…
```

两条实现约束：

1. **原地替换，不能只发一次**。锚点可以"发过就不再发"，计划不行——步骤会完成，摘要必须跟着变。所以 `withPlan` 返回的是"替换掉旧块的新数组"，不是追加。
2. **不能被提前返回吞掉**。`context` 里锚点那一支会在"已发过"时提前 `return undefined`，计划块必须挂在它之后、且各分支都带上（`withPlanOrUndefined` 这类分支每个都要接）。

**审计** —— `as/plan { action: 'created', goal, steps }`；步骤完成的那一种（`step_done`）代码里留了位置，但见下。

**步骤状态没有推进路径**（2026-11-17 核代码确认）：`withPlan` 靠步骤文本以 `✓` 开头来数"完成了几步"，但 `store.completeStep` **全仓无调用点**——没有代码会写 `✓`。所以现在能显示的只有"0/N 步"，计划是静态的。这是计划区下一个要补的口子（`08` B.1 记为 🟡 的原因之一）。
