# 实测记录 22：补救 R2（按线索取回情景摘要）

> 阶段实测记录（当前状态以 [`08-completeness.md`](../08-completeness.md) 为准）。

> 原则（`03` §3）：**先轻后重、先索引后原文、先计划后细节、先澄清后猜测。**

### 底料：摘要要跟着指针落库

之前 `archive_pointer` 只有 `title` + `chars`——能知道"哪轮被移出"，但取不回内容。
R2 要的是**摘要**，所以压缩时把每轮的情景摘要一起存进指针（`summary` 列，含老库迁移）。

### 两条查法，一条工具

`archive` 工具原本只有时间粒度（R3：2026 → 月 → 周 → 天 → 时 → 片段）。现在按 `q` 走 R2：

| 入参 | 走哪一级 | 回什么 |
|---|---|---|
| `q="缓存那次讨论"` | R2 按线索 | 命中摘要（最多 3 条）+ 「这是摘要，不是原话」 |
| `q` 无命中 | R4 | 反问更具体的线索（时间/人名/项目/说过的词），不硬猜 |
| `key="2026-10-26T14"` | R3 按时间 | 原文片段 |

中文没有空格，按词切分匹配不到（"缓存那次的讨论" 对不上 "缓存方案讨论"），
所以线索侧与召回同一套口径：**拉丁词按空格切、CJK 取二元组**。

### 实测

```
播种：缓存方案讨论（摘要：定了进程内 LRU，不用 Redis…）/ 发布流程（灰度 5%→25%→全量）

问：上次我们讨论缓存方案，最后定的是什么？用 archive 工具带 q 查一下再回答。
答：- 用进程内 LRU，不用 Redis
    - 租约续期失败就降级直读主库
    如果你想要当时的原话，我可以再按时间粒度下钻去取原文
```

模型自发走完 R2 → （提议）R3 的阶梯，没有越级去猜原文。
