# 记录 50：世界树 P-b —— 注入行标新旧（时间线补丁①）

> 依据 [`09-world-tree.md`](../09-world-tree.md) §7.3 的补丁①，以及 §11 的 P-b。
> 目标：**让模型在注入里看得出"这条是旧的、什么时候失效的"**。
> 动手时发现只做"标记"不够——所以这一期比原计划多了一半。

## 0. 一句话

> 注入行现在会标 `记忆·旧值｜2026-11-10→2026-11-18`；
> 并且 `recall(..., { history: true })` 会把**同槽的旧值**一起带出来
> （原来被读取侧去重整个挡掉）。**不开启时旧口径一字不变。**

## 1. 先说不那么显然的那一半：只标记是不够的

`09` §7.3 原计划只做一件事：渲染时把 `state` / `t_end` 标出来。
动手前的集成断言直接把这个计划打回来了。

```js
s.add('用户住在上海静安区', { tagPath: '记忆/用户/城市' })
s.addInSlot('用户搬到了杭州滨江', { tagPath: '记忆/用户/城市' })   // 同槽，后者取代前者
s.recall('静安区 滨江', 10)        // → 1 条
```

**只回了 1 条。** 原因在 `recall` 的同槽去重（`01` §5.4.1「叶=槽」）：

```ts
// 同槽只出一条：叶=槽，槽内取现值
const bestInSlot = new Map<string, number>()
...
return ranked.filter((item, index) => leaf === null || bestInSlot.get(leaf) === index)
```

也就是说：**"AI 能同时看到新旧"这个目标，在同槽场景下根本不成立**——
不是"看到了但没标"，是**旧值压根没被返回**。

而"同一个位置的演化"恰恰是最需要同时看到新旧的场景。
所以只加标记等于给一个不存在的行做装饰。

> **教训**：`recall` 的注释写着"默认检索会带上 `superseded` 的旧值（历史常有用）"，
> 读起来像"新旧都给"。实际上这句只在**跨槽**时成立；**同槽**被去重挡掉了。
> 注释与实现不矛盾，但**容易读成相反的意思**——所以要写集成测试，不能只读注释。

## 2. 两半的实现

### 2.1 渲染：只给非现值加东西

```
现值：[记忆｜2026-11-18｜来源:user｜置信:高] 用户现住杭州滨江区
旧值：[记忆·旧值｜2026-11-10→2026-11-18｜来源:user｜置信:高] 用户住在上海静安区
```

- **现值行一字不变**——它是绝大多数行，改它等于给每一轮注入凭空加字数。
- 非现值加三样：状态标记（`旧值` / `已并入` / `已抑制`）、区间（`起→止`）、
  以及**一次**提示句（`标了「旧值」…不要当成当前事实`，只在真混进旧值时出现）。
- **同一天形成、同一天失效时只给一个日期**：`2026-11-18→2026-11-18` 是纯噪音。
  实测真会话里大量如此（同一次对话里写了又改），而"旧值"标记已经说清状态了。

### 2.2 召回：`history` 开关

`recall(cue, limit, exclude, { history: true })` 在**同槽去重之后**多留一条：

| 限制 | 值 | 为什么 |
|---|---|---|
| 只在**现值被选中**时才带旧值 | — | 现值都没入围，旧值没有解释对象 |
| 每个槽最多带 **1 条** | — | 同槽更早的历史价值递减，而预算是硬约束 |
| 整次最多 **2 条** | — | 多槽各带一条时也不至于把候选池挤爆 |
| `latestOnly` 时**不带** | — | 两个开关冲突时以"只要现值"为准 |

**默认不开**：`recall` 不带 `history` 时行为与改造前**完全一致**（单测 9a/9b 钉住）。
只有注入主路径（`index.ts` 的实时旁路）显式传 `true`。

## 3. 真库上的验证

在三轮真会话留下的库（`/tmp/as-pb/pb.db`）上直接跑：

```
=== 库里的条目 ===
  superseded  记忆/居住地 | 用户住在上海静安区
  superseded  (无标签)   | 用户住在杭州滨江区（已从上海静安搬走）
  superseded  记忆/居住地 | 用户住在杭州滨江区
  superseded  记忆/居住地 | 用户住在杭州滨江区（2024年从上海静安区搬来）
  active      记忆/居住地 | 用户现住杭州滨江区，2024年从上海静安区搬来

=== recall 不带 history ===   2 条（现值 + 一条无标签旧值）
=== recall 带 history ===    3 条（多出「用户住在上海静安区」——正是同槽旧值）

=== 渲染 ===
[记忆｜2026-11-18｜来源:user｜置信:高] 用户现住杭州滨江区，2024年从上海静安区搬来
[记忆·旧值｜2026-11-18｜来源:human｜置信:高] 用户住在杭州滨江区（已从上海静安搬走）
[记忆·旧值｜2026-11-18｜来源:user｜置信:高] 用户住在上海静安区
```

（三行的日期都没区间，因为它们同一天形成、同一天失效——正是 §2.1 那条"只给一个日期"在起作用。）

## 4. 测试（28 + 9 项）

`test/inject-render.test.mjs`（28 项）：

| 组 | 钉住什么 |
|---|---|
| 1 | **现值行与改造前完全一致**（回归基线）；只有现值时不出提示 |
| 2 | 旧值：标「旧值」+ 给区间 + 出提示 |
| 3 | `merged` / `suppressed` 各有标记 |
| 4 | `tEnd = 0` 只给起点；**起止同一天只给一个日期**；标记仍在 |
| 5 | 与「摘要 / 节选」标记叠加（`记忆·摘要·旧值`） |
| 6 | 新旧混在一起时两条都能读出来，提示只出一次 |
| 7 | 第 2 轮的「并入原答案」措辞没被破坏 |
| 8 | **集成**：`recall` → `MemoryEntry` → 注入项 → `render` 全链，`state` 与 `t_end` 真的流到了渲染 |

第 8 组是这一期最重要的：前面七组都是手工构造的注入项，
**中间任何一环漏掉 `state`，前面全绿而功能是死的**。它就是在这一步抓出 §1 那个发现的。

`test/slot.test.mjs` 新增第 9 组（9 项）：`history` 的三条限制 + 与 `latestOnly` 的冲突优先级。

## 5. 这一期**没做**什么

- **as-of 查询**（`recall(cue, { at })`）：`09` §7.3 的补丁②，明确延后。
  现在能看"以前是什么"，还不能问"上个月我以为是什么"。
- **标签的时间戳**：`tag` 仍只有 `created`，改名/合并/废弃没有时间轴。
- **`replaced_by` 没用上**：渲染只用了 `state` 与 `t_end`。要显示"被哪条取代"
  需要一次额外查询（拿替换者的标题），留到有需求时。
- **`≤7 字` 仍在代码里**：设计已移除（`09` §5），但那会动行为，另开一期。
