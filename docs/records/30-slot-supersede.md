**写入侧补齐了"一个槽只留一条现值"的语义**：同标签叶里再写一条，旧条目被标

## 一、槽是什么

`01` §5.4.1 回填了一条原文没规定的规则：

> **叶 = 槽，同叶只出一条（取现值）**。标签叶代表"一个可被更新的槽位"，
> 同一槽里的旧值不该重复占位；未挂标签的条目互不相关，不受此限。

`recall()` 早就按这条去重（同叶只返回分数最高的那一条）。缺的是**写入侧**：
它每次写入都新插一条，于是同一个槽里堆着一串同义副本——去重只是把问题挡住了，
库里的重复并没有减少，注入预算、`summary` 的意义都被稀释。

### 为什么不能靠相似度

`store.findSimilar()` 用的是字符二元组 Jaccard，阈值 0.82。它挡得住"复制粘贴"
和"多一个空格"，挡不住**改说法**。记录 29 §4.1 的实证：

```
用户的项目叫 Halcyon，缓存层用进程内 LRU
项目名 Halcyon，缓存层用进程内 LRU
用户的项目 Halcyon 缓存层使用进程内 LRU
项目名 Halcyon，缓存层用进程内 LRU
```

这是同一件事的四次重述。要挡住它，要么把阈值降到会误合并的位置，要么换判据。
**槽位是结构判据，不是相似度判据**：位置（标签叶）已经说明"这两条在讲同一件事"，
不需要再猜字面像不像。记录 20 当年测到 3 条，是因为那时只有几轮；会话一长，
字面判据的漏就露出来了。

### 为什么是 supersede，不是删除，也不是原地改写

| 做法 | 为什么不 |
|---|---|
| 删除旧条目 | 违反 `03` §1 的铁律"遗忘不是删除"。历史是审计与回滚的基础，删了就取不回来 |
| 原地改 `text` | 静默改写历史：`replaced_by`、`as/*` 审计、以及"上一版是什么"全都消失。R5 的"取不回来"也失去依据 |
| 标 `merged` | `merge` 的语义是"信息已被新条目**完全包含**"，默认不再检索；改说法不等于完全包含，旧条目里的措辞与细节仍可能有用 |
| **supersede（采用）** | 只改状态与一个指针：正文、`t_start`、`use_count` 一概不动；默认检索仍能带出旧值，`latestOnly` 才只要现值 |

也就是说，槽里"只留一条现值"靠的是**状态**，不是物理删除——库里同时保留
"现在是什么"和"以前说过什么"。

## 二、实现

### 2.1 `activeInSlot(tagPath)`

```ts
activeInSlot(tagPath: string): MemoryEntry | undefined
```

判据：`tag_id` 指向该路径、`state = 'active'`，按 `t_start` 取最新（同刻取后写入的）。
路径会归一（补 `记忆/` 根、去空段），所以 `项目/Halcyon` 与 `记忆/项目/Halcyon`
查到的是同一个槽。

### 2.2 `addInSlot()`：先取旧值 → 再插入 → 最后标取代

顺序不能换：先插后取会把刚写的那条当成"旧值"，直接自杀。

```ts
const slot = tagPath === undefined || isCatchAll(tagPath) ? undefined : this.activeInSlot(tagPath)
const entry = this.add(text, options)
if (slot === undefined || slotMode() === 'keep') return { entry }
this.supersede(slot.id, entry.id)
return { entry, superseded: slot }
```

`index.ts` 的 `writeMemory()` 调它，并在真发生取代时补一条审计：

```
as/slot_supersede { slot, from, to }
```

审计只记槽名与两条 id，不记正文——审计链不该长成第二份正文。

> **与任务书的一处偏离**：任务书要求把 `add` + `supersede` 的组合直接写在
> `index.ts` 的 `writeMemory()` 里。这里下沉到了 `store.addInSlot()`，理由是
> `index.ts` 是 pi 扩展入口（依赖宿主，测试无法 import），写在里面等于这一组
> 语义**没有任何单测能碰到**。下沉后 29 项断言打的是真路径，`writeMemory()`
> 只剩"调它 + 记审计"两件事。

### 2.3 三条不进入槽位规则的情况

| 情况 | 为什么不取代 |
|---|---|
| 没有 `tagPath` | 未挂标签的条目互不相关，没有槽（`01` §5.4.1 原文） |
| 兜底桶 `其他` / `未分类` | 它们**不是槽**：`WRAPUP_RULES` 把"拿不准"的事实都赶进「其他」，那里装的是互不相关的事。若当槽用，第二条无关事实会把第一条标成被取代——库里还在，但默认召回不再带它，等于悄悄丢了一条 |
| `AS_SLOT=keep` | 显式退回并列，见下 |

### 2.4 `AS_SLOT=keep` 的取舍

默认 `supersede`；`AS_SLOT=keep` 时两条都 `active`（旧行为）。

留这个开关不是"留个后门"，是因为"槽"是**文档级约定**，不是所有用法都成立：
有人会把同一个标签叶当**时间线**用——同一主题下多条并列的事实，每条都该留。
他们的库不该被一次升级顺手改写历史。开关只影响**以后**的写入，不迁移已有条目；
先 `keep` 再关掉时，只取代"现值里最新的那条"，不会把并列的几条一起埋掉。

### 2.5 顺手修的一处：`recall()` 同叶取现值

默认召回会带出 `superseded` 的旧值（历史常有用）。旧值写过很多次，
`salience` 往往比新值高——**只按分数取同叶第一条，返回的会是被取代的那句旧话**。
所以去重从"按分数取第一条"改成"同叶优先现值"：

```ts
if (item.row.state === 'active' && ranked[kept].row.state !== 'active') bestInSlot.set(leaf, index)
```

排序仍是分数序，只在"同叶、一新一旧"时让现值压过分数。

## 三、`summary` 现在被哪两处读

写入时 `judgeDoc()` 会把摘要落库（`store.setSummary`，截 120 字，记录 27 §三）。
此前没有任何消费方（记录 29 记的是"字段有了、写入通了"）。现在两处读它：

| 位置 | 行为 |
|---|---|
| `inject.ts` `render()` | `mode === 'summary'` 时**优先用 `entry.summary`**，空串才退回旧行为（截断正文到 240 字）。摘要本来就是为"给模型定位"写的，长度受控、措辞稳定 |
| `turns.ts` `titleOf()` | 索引行标题优先用该轮的情景摘要（`ArchiveRef.summary`）前 12 字，没有摘要才退回首条消息正文前 12 字。索引行的用途是"我忘了什么、去哪找"，摘要比正文开头更能定位 |

`inject.ts` 的 `InjectItem` 加了可选 `summary?: string`；`index.ts` 组装注入条目时
`entry` 本身就是 `MemoryEntry`，展开即带上，不需要额外接线。

单测里值得点名的几条：

- **2b**：旧值显著性更高（0.9 vs 0.6）时，默认召回仍给新值——钉住"现值优先压过分数"；
- **4c**：`keep` 关掉之后恢复取代，且只动最新那条，不会把并列的历史一起埋掉；
- **7c**：不受信任会话写入后，槽里的现值仍是原来那条（写入根本没进 `memory_entry`）；
- **8a / 8b**：「其他」兜底桶里两条互不取代——这是"槽 = 可被更新的位置"与"桶 = 什么都装"的分界。

**没验到的**：真会话里模型是否会配合"用同一个槽名"（`WRAPUP_RULES` 加了一句约束，
但它是提示词，不是硬约束）；不同措辞落在**不同**叶子时仍会各留一条——那是自动归类
的活（`records/note-auto-classification.md`），不在这一批。

## 补记：端到端已验证（同日，21:55）

单测之后又用真会话跑了一遍，两轮写同一件事、第二轮是更正：

```
第 1 轮：记住：我的项目叫 Halcyon，缓存层用进程内 LRU。
第 2 轮：更正：项目名改成 Halcyon-Pro 了，缓存仍然是进程内 LRU。
```

库里的结果（`AS_MAINT_EVERY=0`，只留收尾相一条写入路径）：

```
active      tag=记忆/技术选型   「Halcyon-Pro 的缓存层使用进程内 LRU」
active      tag=记忆/项目       「用户的项目名已改为 Halcyon-Pro」
superseded  tag=记忆/技术选型   → m-mwkqerca-2   「Halcyon 的缓存层使用进程内 LRU」
superseded  tag=记忆/项目       → m-mwkqera8-1   「用户的项目叫 Halcyon」
```

审计：`as/slot_supersede {slot:"记忆/技术选型", from, to}`、`{slot:"记忆/项目", from, to}` 各一条。

**四个要点都成立**：
1. 同槽只留一条 active，旧条目**没被删**（正文、状态、指针都在）；
2. 两个槽各自独立（项目名与选型互不干扰）；
3. 默认召回只出现值：`['用户的项目名已改为 Halcyon-Pro', 'Halcyon-Pro 的缓存层使用进程内 LR…']`，
   `latestOnly` 结果相同——旧值即使分数更高也不抢；
4. 模型确实**复用了槽名**（`WRAPUP_RULES` 那句约束生效）——两轮的标签路径一模一样。
