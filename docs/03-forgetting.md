# 遗忘与归档机制方案

> 核心理念：单次超长对话“不溢出”不是靠粗暴截断，而是靠**对旧上下文按需逐项调整**——重要的保留，不重要的只留摘要与可定位索引。
> 本文写设计规范；实现进度见 [`08-completeness.md`](08-completeness.md) B 表。

---

## 1. 骨架：五区 + 硬预算

**每次模型调用前只称重，不重新分区**；只在越过预算阈值时对历史消息执行调整：

```text
可用预算 = 上下文窗口 − 输出预留（AS_RESERVE，默认 8192 token）
```

| 分区 | 内容 | 策略 |
|---|---|---|
| **不可移出** | L0/L1/L2 锚点、安全/剔除标记、计划摘要、保护轮（`turn_mark` + 工具轮） | 绝对优先保留；压缩与折叠先削可压缩区 |
| **计划区** | 计划目标、步骤状态（`✓`）、开放问题 | 摘要每请求前置注入，不随旧轮被压丢 |
| **工作区** | 最近 `AS_KEEP_RECENT` 轮原文 + **末轮无条件保护** | 原样保留在请求内 |
| **可压缩** | 更早的对话轮次、重复轮、冗长工具输出 | 摘要 / 判重占位 / 折叠 / 移出视图 |
| **索引区** | 索引行（日期+标题+字数+指引）、`archive_pointer`、情景摘要、会话备注、来源与置信 | 几乎不占原文预算，支撑 R2/R3 补救检索 |

**三档策略阈值**：
- **70% 预警**：记录 `as/warn` 审计，提醒压力接近阈值。
- **85% 限制与压缩**：过滤低显著记忆（仅放行 `salience ≥ 0.8` 或 `pinned`、注入上限减半且至少 1 条），触发按轮视图压缩 / 折叠。
- **95% 冻结注入**：冻结常规记忆注入（锚点、计划与剔除清单不冻），执行保底折叠。

**同源「已移出可恢复」铁律**：三条压缩路径（按轮压缩、纪要压缩、确定性折叠）统一调用 [`recover.ts`](../pi/src/recover.ts)，同时产出**指引文案**与库内 **`archive_pointer`**；若某段无法建立归档指针（如缺时间戳或无会话文件），指引必须明说「未能建归档指针（原因）」，严禁只给检索指引却无指针导致模型查不到转而虚构。

## 2. 操作集（七种，不含物理删除）

| 操作 | 语义 | 可恢复性 |
|---|---|---|
| **压缩** | 旧轮 → 情景纪要 / 按轮压缩文本 | 原文在会话存档，指针可回溯 |
| **去重** | 字面去重合并（`merge`）与同槽取代（`supersede`） | 保留正文、`replaced_by` 与来源 |
| **降权** | 降低自动注入排序权重（`salience` 评分衰减或 `decay()`） | 可通过判用恢复，不改正文 |
| **移出上下文** | 从本次发送视图移除，替换为索引行或占位 | 存档不动，保留索引与指针 |
| **索引化** | 世界树位置标签 + 线索 / 实体 / 时间标签（演进见 `09` 与 `records/38`） | 支持跨表达定位检索 |
| **归档** | 会话原文按时间桶索引化 | 审计可回放，人可直读 |
| **脱敏** | 替换高置信凭据片段为 `[已脱敏:<kind>]`，保留上下文结构 | 写侧 + 二次扫描 + 深度消毒三道防线 |

**铁律：移出 ≠ 删除。** 移出只作用于发送视图，记忆与会话原文均保留。

## 3. 补救阶梯：R2–R5

遵循原则：**先轻后重、先索引后原文、先澄清后猜测**（原构思的 R1 计划板回放已取消，计划改为轻量摘要区直接注入）。

| 级 | 方式 | 触发场景与约束 |
|---|---|---|
| **R2** | 按线索取回情景摘要 | 调用 `archive(q)` 检索指针 `title + summary`（≤3 条 × ≤300 字，每轮限 2 次防抖动） |
| **R3** | 按归档指针回原文片段 | 调用 `archive(key)` 按 `所有→年→月→周→天→时` 六层下钻，命中 ≤3 段早停给片段 |
| **R4** | 向用户澄清 | 线索不足且检索零命中时主动反问用户给线索（时间、项目或人物） |
| **R5** | 承认不可恢复 | 区分「没发生过」（`empty-archive`/`bucket-empty`）与「找不到了」（`source-gone`/`range-empty`），禁止编造细节 |

### 3.1 计划区保护措施

计划只以轻量摘要存在 `plan` 表中并在每次请求时前置注入视图（不建重型外部计划板），配两道防丢失机制：
1. **压缩提示词约束**：`TURN_RULES` 要求按轮压缩保留结论、约束与未完成步骤。
2. **不可移出区绝对优先权**：计划摘要块打上 `zone: 'plan'` 非枚举标记并有内容特征兜底，`segmentTurns` 与 `planFold` 在任意压缩压力下优先保留计划块。

### 3.2 会话备注与归档定义

- **归档即会话**：归档不是第二份拷贝，而是所有持久化的会话日志本身；`archive_pointer` 只记录位置与情景摘要。
- **备注是用户注脚**：由人通过 `/as-note` 挂在**会话**上（不挂在单条对话或时间桶上），不注入主 AI 上下文，与时间下钻并列作为人侧检索入口（`/as-archive <关键词>` 只匹配备注，不搜对话正文）。

## 4. 与 Pi 宿主的接缝

| 机制 | Pi 原生能力 | 本扩展处置 |
|---|---|---|
| Agent 循环与续步 | `pi-agent-core` + `agent_before_settle` `continue` | 扩展通过 `AS_MAX_ROUNDS` 控制句内多轮上限 |
| 非破坏性视图 | `context` 钩子 | 唯一修改发送消息处，存档不写回 |
| 内置裁剪 | `ctx.compact()` | **默认关闭**（`AS_COMPACT=1` 才开）。因宿主裁剪按 step 边界且 `abort()`、不写归档指针，统一由扩展按轮压缩与折叠接管 |
| 会话持久化 | 宿主 jsonl 文件 + `SessionManager.listAll()` | 直接作为归档库物理载体 |

## 5. 不可移出区维护：批量打标 + 未审尾巴

为避免“每次调用都扫全量打标”的延迟开销与“还未打标就被压缩”的竞态，采用**周期批量 + 尾巴当场兜底**：

1. **维护旁路**：每隔 `AS_MAINT_EVERY`（默认 10）个用户轮，在后台批量给该窗口内的重要轮次写入 `turn_mark`（键为首条用户消息时间戳）。
2. **压缩时刻**：已打标轮次在 `segmentTurns` 中标记为 `protected`（只读可见，可参与判重但原文不改写）；尚未轮到维护周期的新增尾巴（数量天然受限于个位数轮次）若遇压缩，交压缩旁路当场保留未完成约束与重要事实。
3. **双保险记忆**：用户明确表达的事实、约定和纠正除保护当前轮外，还会由记忆旁路非阻塞相写入 `memory_entry`（`origin: 'user'`），确保即使将来该轮移出上下文，长期记忆仍可召回。
