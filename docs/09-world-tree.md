# 世界树（树图混合 + 时间线 + 多树挂载）

> **定位**：记忆的坐标与演化系统（原「标签树」重构后的现行规范）。
> **实施状态**：P-a / P-b / P-c 已落地（见 [`records/49`](records/49-entry-tag-p-a.md)–[`51`](records/51-tree-mount-p-c.md)）；P-d 起待实施，权威核对见 [`08-completeness.md`](08-completeness.md)。

---

## 0. 一句话

**世界树 = 主干（标签树，管位置与作用域）+ 藤蔓（双向链接，管跨枝跃迁）+ 时间线（管同一位置的演化）。**
主干解"这条属于哪、前提是什么"，藤蔓解"两条分处不同枝的脑洞怎么打通"，
时间线解"这个位置以前是什么、现在是什么"。三样缺一样都会退化：缺主干成意大利面，
缺藤蔓被单父节点割裂，缺时间线则"更新"看起来像"丢失"。

## 1. 先认一件事：旧设计里的「叶=槽」被收窄了

旧设计（2026-11-17 版）说：

> **叶 = 槽，同叶只出一条（取现值）**。一个标签叶代表一个可被更新的槽位。

这条在**单标签**时代是对的，而且解决了一个真问题：记录 29 §4.1 的实证——六轮对话长出 18 条记忆、
大半是同一件事的不同说法，而它们两两之间的字符二元组 Jaccard **都不到 0.82**，`findSimilar` 挡不住。

但只要允许**一条记忆挂多个标签**（参考文档的核心主张），这条就**立刻变成数据丢失源**：

> 两条独立事实都挂 `记忆/世界/机制/API` → 后者取代前者 → **第一条被静默吃掉**。

所以本版把它收窄成：

| | 旧 | 新 |
|---|---|---|
| 谁的规则 | **所有**标签叶 | **只有主标签** |
| 语义 | 一个叶只能有一个现值 | 一条记忆的**主标签**是它的"位置"，同主标签取代 |
| 附加标签 | 不存在 | **可装多条、不取代** |
| 一句话 | 叶=槽 | **位置=槽，归类=文件夹** |

**并且"槽"要按时间理解**（§7）：不是"只能有一条"，而是"**同一时刻只能有一条**"。

## 3. 结构：三个部件

```
记忆                                   ← 根（代码级保护，不可合并/修剪）
├─ 世界
│  ├─ 机制
│  │  └─ API接口                       ← 主标签：这条记忆的「位置」
│  └─ 势力
│     └─ 圣环教会
│        └─ 归序使
└─ 其他                                ← 兜底桶（不是位置）
```

| 部件 | 管什么 | 基数 | 落在哪 |
|---|---|---|---|
| **主标签** | 属于哪儿；**作用域与前提**从这条路径继承 | 一条记忆 **1 个** | `memory_entry.tag_id`（现状，不动） |
| **附加标签** | 还与什么有关；**跨枝归类** | **0..N 个** | 新表 `entry_tag`（§10） |
| **双向链接** | 两条分处不同枝的记忆之间的**语义跃迁** | **0..N 条边** | `memory_link`（**已有**，记录 17） |
| **时间戳** | 这个位置**什么时候**是这个值 | 每条一对区间 | `t_start` / `t_end`（**已有**，记录 34） |

**时间与链接都已经实现了**，缺的是"用起来"：时间缺渲染（§7），链接缺按名字解析（§4.3）。

### 3.1 为什么"主标签=槽"反而能解「单父节点暴政」

参考文档批评：一个"用过期预言当货币的地下黑市"该放 `经济制度`、`预言API` 还是 `黑市势力`？

**取代语义并不要求你选**——它要求你**细化到正确粒度**：

- 说不清放哪，说明**位置还不够细**：`世界/势力/黑市势力/过期预言黑市` 才是位置；
- `经济制度`、`预言API` 是**附加标签**（多值，不取代）；
- 想看"所有用到预言 API 的东西" → 查附加标签，跨枝聚合。

文件系统的同一个道理：两个文件塞进同一文件夹不是"文件夹的限制"，是**归类没做到位**。

## 4. 树图混合的三个效果

### 4.1 上下文继承：读深层条目时，祖先枝是它的前提

参考文档：「父节点（星曦底层法则、圣环教会教义）会自动成为子节点的背景前提，
不需要像世界书那样在每个词条里硬塞重复的触发词」。

**落地**：`recall()` 命中 `记忆/世界/势力/圣环教会/归序使` 下的记忆时，把**祖先路径上**的记忆
纳入候选，但**降一档相关度**（它们是背景，不是答案）。

- 每个祖先枝最多带 **1 条**，整次召回**祖先总量 ≤ 2 条**；
- 计进注入预算，与普通候选同一本账；
- 祖先条目**与线索零重叠也照样带**（"前提"本来就不该被线索命中）；
- 审计记 `as/ancestor { count }`。

> **这是"世界书 vs 世界树"的分水岭**。没有这条，世界树只是"带层级的标签"。

### 4.2 范围剪枝

候选先按主标签的**一级枝**分组；**候选数超过注入预算**时，只保留命中数最多的前 **2** 枝。

- **只在超预算时剪**——剪枝是防爆上下文，不是"更聪明"；
- 被剪掉的枝记 `as/prune { branches, dropped }`；
- 锚点 / 计划 / 剔除清单**永不参与剪枝**（不可移出区）。

### 4.3 跨枝跃迁：`[[名字]]` 要解析成边

`memory_link` 已有（一跳带出 + 污点传播）。缺的是**按名字解析**：

1. **第一步（本轮设计范围）**：`LINK` 给的是**名字**时按名字找——
   **唯一命中** → 建边；**零命中** → 不建不猜，回执"没有这个条目"；
   **多命中** → 不建，候选还给旁路挑一次。
2. **第二步（暂不做）**：正文里直接写 `[[...]]`。要与"剔除后的发送视图"协调，等第一步的命中率。

**边的端点只有条目，没有标签**：边的语义是"这两条说的是同一件事的两面"，那是**内容之间**的关系。
标签之间的关系已由路径前缀表达，再加一套边会长出"同一信息两条通路"。

## 5. 取代「单条 ≤7 字」：路径预算 + 复用率

### 5.1 旧规则的实质

7 字不是为省空间，它是一个**代理判据**，替的是"长成一句话它就不是位置，是摘要"。
代理判据会误伤（`进程内LRU` 是位置）也会漏放（某个被复用 20 次的 API 全名也是位置）。

### 5.2 新方案：三层，都不判单条字号

| 层 | 约束 | 值 | 为什么是它 |
|---|---|---|---|
| **硬兜底** | 单条**路径**总长（含 `/`） | **≤ 96 字** | 成本的真实单位是**路径**（注入要渲染整条），不是单段 |
| **总量预算** | 一条记忆的**全部**标签路径字数之和 | **≤ 200 字** | 多标签下摊薄；超了要求旁路**合并**，不截断 |
| **复用率** | 孤儿枝：`tagUsage()` 里 `total == 1` 且路径 > 24 字 | 维护旁路合并/上提/剪掉 | **本质判据**：只被用过一次的枝不是位置，是笔记 |

**单条（单段）字数不设上限**——本次明确移除的那条。

**孤儿枝收口默认不启用**（用户裁定 I）：它会产生"误伤新建枝"的风险，
所以留成显式开关 `AS_TAG_ORPHAN=1`，且**先只报告不动作**（出体检清单）。

### 5.3 为什么"复用率"比"字数"更根本

- 一个枝被 **20 条**用过 → 它是位置，再长也是位置；
- 一个枝只被 **1 条**用过 → 它不是位置，是**那条记忆自己的摘要**——不管它多短。

字数只是"是不是摘要"的**弱相关特征**；复用数是**定义本身**。而且它可度量、可自动化。

## 6. 别名：只解析，不建节点

用户答复：**继续叫「记忆」，但允许写别名。**

```
tag_alias(alias TEXT PRIMARY KEY, canonical TEXT NOT NULL, created INTEGER)
```

- **解析**：最长前缀匹配——`世界/机制` 命中别名 `世界`，拼出 `记忆/机制`。
- **只解析，不建节点**：别名不产生第二条路径、不产生第二个叶子。
  一个概念只有一个叶子，否则"同主标签取代"与"按路径剪枝"全部失效。
- **用在**：`normalizeTagPath()`（写入）与召回时的路径比对。**读取永远返回规范路径**。
- **谁写**：人侧命令 + 维护旁路（改名时顺手记一条，旧写法继续可用）。

> 别名是**输入侧的字面糖**，不是数据模型的一部分。一旦别名能"新建节点"，
> 它就变成"同一概念两个位置"，那正是 §1 要消灭的东西。

## 7. 时间线：现方案 vs 你初设定 vs 新方案

你的初设定：**「标签或标签内的条目都带有时间戳，或者在时间线框架中运作，AI 读取时能同时看到新旧」**。

### 7.1 时间线要素现状（P-b 落地后）

| 要素 | 现状 | 证据 |
|---|---|---|
| 条目带时间戳 | ✅ | `memory_entry.t_start` / `t_end`；注入行渲染日期或区间 |
| 新旧**都**召回 | ✅ | `recall` 默认带跨槽旧值；传入 `{ history: true }` 可在同槽带出 1 条旧值（整次 ≤ 2） |
| 新旧**关系**可见 | ✅（P-b） | 非现值渲染为 `[记忆·旧值｜起→止]`（同日仅给单日）与提示句；现值行不变 |
| 标签带时间戳 | ❌ | `tag` 只有 `created`，没有 `t_end` |
| 时间线框架（as-of） | ❌ | 尚未实现 `recall(cue, { at })` 时点查询 |

### 7.2 三个方案对比

| | 现方案（状态机） | 你初设定（时间线） | 新方案（主/附标签） |
|---|---|---|---|
| 解决的问题 | 取代与遗忘的**状态** | 同一位置的**演化** | **多维归类** |
| 表达力 | "B 取代了 A" | "A 在 [t1,t2) 是现值，B 从 t2 起是现值" | "这条同时属于三根枝" |
| AI 看到 | 两条并列，**要自己看日期猜谁新** | 明确的新旧与区间 | 跨枝的同类 |
| 代价 | 低（已有） | 中（渲染 + as-of 索引） | 中（`entry_tag`） |
| 与另两个的关系 | **时间线的退化版** | **包含**状态机 | **正交** |

### 7.3 结论：不是三选一

**时间线是现方案的超集，新方案是正交的另一维。** 而且现方案已经有 90% 的地基——
`t_start` / `t_end` / `replaced_by` 三个字段就是区间的雏形。差的只有两块：

| 补丁 | 做什么 | 成本 | 状态 |
|---|---|---|---|
| **① 渲染标关系** | 注入行加「旧值｜起→止」与 `history` 带出同槽旧值 | 小 | **已落地（P-b，记录 50）** |
| **② as-of 查询** | `recall(cue, { at })` → 那个时点的现值；索引 `(tag_id, t_start, t_end)` | 中 | **延后**（暂缺需求驱动） |

**它让「主标签=槽」的语义更干净**：

> **槽不是"只能有一条"，而是"同一时刻只能有一条"。**

这条恰好解释了为什么 `recall` 默认带 `superseded` 是对的——它本来就在给你看时间线，只是没标关系。

**代价要说清**：①会让注入行变长（每行多 10–20 字），而注入预算是硬约束。
所以只在**确实有 `replaced_by` 或 `state='superseded'`** 时加，现值的行不加。
②的索引是纯加法，但查询路径要动 `recall` 的 SQL，属于"要小心"的一类。

## 8. 解耦：多棵树 + 挂载

需求：**把一棵根名为 `碧蓝航线`（或任何别名）的独立世界树，挂到当前世界树的任意标签下。**

这是**文件系统的挂载**，不是"复制进来"。复制会失去解耦：改子树要重新复制，两边会漂移。

### 8.1 模型

```
tree(id, name UNIQUE, created)                        -- 每棵树一行；主树 name = '记忆'
tag(..., tree_id)                                     -- 新增列；主树恒 'main'
mount(id, parent_tag_id UNIQUE, tree_id UNIQUE,
      readonly INTEGER, created)                      -- 挂载点
```

- **挂载点是一个真实的标签**（在主树里可见、可继承、可剪枝、可挂自己的记忆），
  但它的**子内容**来自另一棵树。
- **全局路径是算出来的视图，不落库**：

```
记忆/项目/碧蓝航线/舰船/企业
└─ main ─┘└─ 挂载点 ─┘└ 子树路径 ┘
```

### 8.2 六条约束（每条都有理由）

| # | 约束 | 理由 |
|---|---|---|
| 1 | **单根不破**：AI 看到的命名空间仍是一个根 `记忆` | "单根"是**命名空间**的属性，不是数据库里只能有一棵树。子树是**挂上来的枝**，不是第二个根 |
| 2 | **卸载不删内容**：卸只删 `mount` 行，子树与其中的记忆一条不动 | 与"遗忘 ≠ 删除"同一条原则 |
| 3 | **一棵子树同时只挂一处** | 路径是唯一标识。多挂会让"这条记忆在哪"有两个答案——与"位置=身份"冲突。（filesystem 的 bind mount 是"同一份数据多个入口"，我们的位置是身份，不是入口） |
| 4 | **不许成环**：A 挂 B、B 挂 A → 拒绝 | 否则路径解析与祖先继承都会死循环。挂载时沿 `mount` 链检测 |
| 5 | **根名全局唯一**（`tree.name UNIQUE`） | 这条让 `tag.path` 的 `UNIQUE` **不用动**：每棵树的路径都以自己的根名开头，天然不撞 |
| 6 | **默认可写**，`readonly=1` 拒写；写挂载点下的记忆记 `as/mount_write` | 挂上来的子树可能是"别人的设定"，要能只读引用 |

### 8.3 为什么这次是"纯加法"

`tag.path` 现在是 `TEXT NOT NULL UNIQUE`。看起来挂载会破坏它（两棵树都有 `项目`），
但**每棵树的路径都以自己的根名开头**：`记忆/项目` vs `碧蓝航线/项目`——**天然不撞**。

- **不用重建 `tag` 表**（SQLite 改 UNIQUE 要整表重建，很脏）；
- **不改 `tag.path` 的含义**（仍是树内完整路径，含根名）；
- 只需加 `tree` / `mount` 两张表 + `tag.tree_id` 一列（有默认值，老库直接 ALTER）。

### 8.4 路径解析：最长挂载点前缀

全局路径 → 定位，三步：

1. 在主树里找**最长的挂载点前缀**：`记忆/项目/碧蓝航线` 是挂载点 → 跳树；
2. 剩余段 `舰船/企业` 拼上子树根名 → `碧蓝航线/舰船/企业`；
3. 在子树里按普通路径查。

反向（给定一条记忆，求它的全局路径）：查它的 `tree_id` → 若不是主树，找挂它的 `mount` →
递归前置挂载点的全局路径。因为约束 3（只挂一处）与约束 4（无环），这个递归一定终止。

### 8.5 对现有代码的影响（诚实清单）

| 位置 | 要不要改 | 说明 |
|---|---|---|
| `recall` 的**段名匹配** | **不用改** | 它按 `tag_path.split('/')` 逐段匹配，树内路径照样能匹配。这是这次设计最大的运气 |
| `recall` 的**候选范围** | **要改** | 只召回**当前可达**的树（主树 + 挂载链）。未被挂载的子树**不参与**——这就是"解耦"的收益 |
| `tagUsage` 的 `startsWith` | 不用改 | 树内前缀，语义不变。跨挂载的"整棵子树总量"另算 |
| `activeInSlot` / `ensureTag` | 加 `treeId` 参数 | 默认主树，老调用点不变 |
| **注入渲染的路径** | **要改** | 给模型看**全局路径**（`记忆/项目/碧蓝航线/舰船`），不是树内路径 |
| 剪枝的一级枝分组 | 要改 | 一级枝在全局路径的第一段 |
| 祖先继承 | 要跨挂载 | 挂载点本身算祖先 |
| 审计 | 要加 | `as/mount { action: attach 或 detach, parent, tree }` |

### 8.6 与"别名"的分工（容易混，写清）

| | 别名（§6） | 挂载（§8） |
|---|---|---|
| 指向 | **同一个节点**的另一个写法 | **另一棵树** |
| 落库 | 不产生节点 | 产生一条 `mount` 行 + 一个挂载点标签 |
| 路径 | 解析后仍是主树路径 | 解析后**换树** |
| 能不能有内容 | 无（就是个名字） | 有（挂载点自己可以挂记忆） |

## 9. 与旧设计的冲突与代价（点名）

| 项 | 旧 | 新 | 代价 / 风险 |
|---|---|---|---|
| **叶=槽** | 所有标签叶 | **只有主标签** | 附加标签上的同义副本不再自动取代。缓解：附加标签只放"归类"、主标签放"事实"；`findSimilar` 与维护旁路合并仍在 |
| **单条 ≤7 字** | 硬规则 | **取消** | 可能出现 30 字的位置。缓解：总量预算 + 孤儿枝体检（默认不启用） |
| **一条一标签** | `tag_id` 单列 | 主 + 附加（`entry_tag`） | 数据模型要动；`JOIN tag ON t.id = m.tag_id` 的查询要确认是否该改成"任一路径命中" |
| **同叶去重（读侧）** | 按主标签去重 | 不变（主标签仍是槽） | 附加标签不参与去重 → 同一批记忆可能重复入围。缓解：候选按 `entry_id` 一维排列，天然去重 |
| **单库单树** | 一棵树、一个根 | 多树 + 挂载 | `recall` 的候选范围要加 `tree_id` 过滤；注入渲染要换成全局路径 |
| **时间线** | 状态机 + 时间戳，不标关系 | 补渲染标关系 | 注入行变长 10–20 字/行，只在真有 `replaced_by` 时加 |

## 10. 数据模型变更（**要拍板顺序**）

```sql
-- ① 多值归类（F：先做）
CREATE TABLE IF NOT EXISTS entry_tag (
  entry_id TEXT NOT NULL,
  tag_id   TEXT NOT NULL,
  created  INTEGER NOT NULL,
  PRIMARY KEY (entry_id, tag_id)
);

-- ② 别名（J：任意路径）
CREATE TABLE IF NOT EXISTS tag_alias (
  alias     TEXT PRIMARY KEY,
  canonical TEXT NOT NULL,
  created   INTEGER NOT NULL
);

-- ③ 多树（L）
CREATE TABLE IF NOT EXISTS tree (
  id      TEXT PRIMARY KEY,          -- 'main' / 't-xxxx'
  name    TEXT NOT NULL UNIQUE,      -- 根名：'记忆' / '碧蓝航线'
  created INTEGER NOT NULL
);

-- ④ 挂载（L）
CREATE TABLE IF NOT EXISTS mount (
  id            TEXT PRIMARY KEY,
  parent_tag_id TEXT NOT NULL UNIQUE,  -- 一个挂载点只挂一棵
  tree_id       TEXT NOT NULL UNIQUE,  -- 一棵树只挂一处
  readonly      INTEGER NOT NULL DEFAULT 0,
  created       INTEGER NOT NULL
);

-- ⑤ tag 加一列（有默认值，老库可直接 ALTER）
ALTER TABLE tag ADD COLUMN tree_id TEXT NOT NULL DEFAULT 'main';
```

**不变量（代码保证 + 单测钉住）**：

1. `memory_entry.tag_id` 非空 ⇒ `(entry_id, tag_id)` **必在 `entry_tag` 里**
2. `entry_tag` 指向的路径必须是**已存在的枝**
3. `tag_alias.canonical` 必须是规范路径（**别名不能指向别名**）
4. `mount` 无环；`mount.tree_id` 所指的树**不是主树**
5. 未被挂载的树，其记忆**不参与** `recall`

**迁移**：① 回填 `INSERT INTO entry_tag SELECT id, tag_id, t_start FROM memory_entry WHERE tag_id IS NOT NULL`；
③④⑤ 老库全部落到 `main` / 无挂载——**行为一字不变**。

## 13. 一句话给 `08`

> **世界树 = 主干（主标签=位置与作用域）+ 藤蔓（`memory_link`）+ 时间线（`t_start`/`t_end`/`replaced_by`）。**
> 十项已定：文件系统形态/节点叫标签 · 取消单条字数限制（路径预算 + 复用率，孤儿枝收口默认**不启用**）·
> 单根 · 根名 `记忆` + 别名（只解析）· 树图混合 · `entry_tag` 先做 · 继承 1/2/×0.7 · 剪枝留 2 ·
> 别名任意路径 · **多树挂载**（`tree` + `mount`，一棵子树只挂一处、不许成环、卸载不删内容）。
> **核心修订：叶=槽 收窄为"主标签的语义"，且槽按时间理解——"同一时刻只能有一条"。**
> **已落地 P-a / P-b / P-c**（记录 49 / 50 / 51），三期各自"明确没做"的清单见 §11.1；
> **P-d 是下一期，也是第一处真的会动行为的一期**（`resolveTag` + 可达树过滤 + 渲染换全局路径）。
> 当前口径：**召回还没有可达树过滤**，未挂载的树的记忆仍会被召回——别以为解耦已生效。
