# 隔离设计

> 隔离不是单一开关，而是**四种权限（V / W / J / I）在十个边界上的正交分配**。
> 本文写设计规范；每条边界的实测落地状态以 [`08-completeness.md`](08-completeness.md) D 表为准。

---

## 0. 已定裁定（A1–A10）

| # | 议题 | 裁定 | 结构影响 |
|---|---|---|---|
| A1 | 审批者能否看最新用户消息 | **不能** | 主 AI 的思考已包含相关信息；B3 实行完全原文隔离 |
| A2 | R4 剔除是否等人工 | **自动执行** | 不挂起等人工；安全性靠“极低触发率 + 可回滚 + 全审计”承担 |
| A3 | 跨会话记忆是否共享 | **共享** | 仅按 profile 隔离记忆；跨会话是预期通路而非泄漏 |
| A4 | 人格能否导出到别的 profile | **只允许整包**（整份配置或整场会话） | 禁止逐条搬运；导入内容标「此会话的上下文仅供参考」并降级为 `imported` |
| A5 | 主 AI 与审批机制 | **常态标准化，罕见才当闸门** | 常态把口语声明翻译成标准命令；但审批者是 AI，不预设放行倾向，风险信号出现时拦截 |
| A6 | 人能否直读归档 | **可以** | 归档就是会话上下文本身，归档库就是所有会话；分阶段下钻只约束 AI |
| A7 | 什么算“大改” | **不设静态判定线** | 模型判断风险，代码映射后果，三条硬不变量不可谈 |
| A8 | 剔除以何为载体 | **发送视图净化** | 发送视图 = 存档 + 剔除清单现算，存档不动；pi 上影响下一次请求 |
| A9 | 导入内容如何采纳 | **会话级信任**（VS Code 受限模式） | 不受信任会话可读不可写，全部写入进 `pending_write` 待人批量或逐条采纳 |
| A10 | 主 AI 与“黑盒”的关系（修正 A5） | **知道有门，不知门后** | `change` 对主 AI 是“声明”而非申请；知道可提请及成功与否，不知谁审、标准与阈值 |

## 1. 四种权限的正交原则

| 代号 | 权限 | 含义 | 失控后果 |
|---|---|---|---|
| **V** | 可见 | 能否读到对方数据、状态、历史 | 信息泄漏 → 被针对性操纵 |
| **W** | 写入 | 能否改变存储、锚点、预算 | 篡改 → 不可信 |
| **J** | 裁决 | 能否决定一件事做不做 | 自我批准 → 门控失效 |
| **I** | 影响 | 能否改变对方下一次行为 | 隐性操纵 → 无法追责 |

两条不可违背的推论：
1. 同时拥有 **W 和 J** 的主体会自我批准 → 旁路只能建议，代码服务才执行。
2. 同时拥有 **I 和 J** 的主体能既下药又开药方 → 记忆旁路（有 I）无权裁决大改，审批者（有 J）不能污染上下文。

## 2. 十个边界

### B1 主 AI ⟂ 基础设施（黑盒边界）

- **隔离**：主 AI 看不见记忆 ID、存储结构、`salience` / `trust`、预算与审计；只能通过 `memory` 与 `change` 两个写原语表达意愿，不能直接写库。
- **落盘形态取舍（B1-a）**：记忆库必须落盘以维持跨会话连续性，采用 `node:sqlite` 二进制页格式单文件（非明文 JSON），使模型无法用文本 `grep` 顺手读取。
- **残余风险（诚实边界）**：二进制格式是提高直读门槛而非加密；在桌面 CLI 宿主上模型若拥有 shell 工具，仍可在系统级访问库文件。真正物理封死需宿主替换 `FileSystem` provider 与进程级沙箱。

### B2 主 AI ⟂ 审批者

- **隔离**：贯彻 A10——**知道存在、不知道机制**。主 AI 可发起 `change` 声明并得知是否被受理/驳回，但不知道审批者身份、角色数量、判定标准、阈值与历史裁决理由；回执措辞保持中性，防止模型学会写“讨好审批器”的理由。

### B3 审批者 ⟂ 原始上下文（D13）

- **隔离**：审批者（[`approve.ts`](../pi/src/approve.ts)）只看结构化反思、变更声明、干净的 L0/L1 锚点与历史已批变更链；**不给对话原文、主 AI 当前叙事及最新一条用户消息**。
- **原因**：防止审批者与主 AI 读取同一份受污染上下文而一起被误导。代价是若主 AI 已被操纵，其转述的意图本身可能已变形，需靠历史对照与人类抽检兜底。

### B4 来源隔离与污点传播

- **隔离**：`human / user / archive / model / external / imported` 六类来源严格分层，不可混淆升格。
- **传播规则**：通过联想边带出或计算有效可信度时，**一跳取最不可信**（`min(自身, 一跳邻居)`）；只传一跳以避免单条 `imported` 记忆令整个连通分量塌陷。

### B5 旁路之间 ⟂（存储层写能力分级）

- **机制**：不再依赖“旁路自觉只写自己那部分”，而是在 [`store.ts`](../pi/src/store.ts) 通过 `store.scoped(...capabilities)` 强制隔离：
  - `memory.write / touch / suppress / supersede`：收尾相、维护旁路、交涉通道（按各自所需能力授出）；
  - `relation.write`：维护旁路（标签与联想边）；
  - `tree.write`：**单独拆分**给人侧管理，不授予维护旁路（防止其擅自挂载整棵外来树）；
  - `redaction.write` / `plan.write`：记忆旁路阻塞相；
  - `anchor.write`：大改审批链；
  - `pointer.write`：压缩模块；
  - `trust.write`：**仅人侧命令**；
  - `audit.write`：内部记账。
- **硬保障**：构造时运行 `verifyCapabilityTable()` 校验能力表与方法实现零漂移；越权调用抛 `CapabilityError` 并记 `as/capability_denied`（审计仅记方法名与能力名，不含入参原文）。严格直调闸门由 `AS_CAPABILITY=1` 控制。

### B6 监督与剔除载体（B6-a）

- **载体**：**发送视图 = 存档 + 剔除清单现算**（纯函数 `applyRedactions()`）。归档即会话日志本身，永不改写历史原文。
- **Pi 上的边界**：Pi 没有“中止当前 step 并重发”的入口，剔除仅影响**下一次请求**的发送视图，配合 `suppressDerived()` 作废本轮衍生记忆写入。因无人工事前否决，触发门槛必须极严，靠审计链与可撤销清单兜底。

### B7 profile ⟂ profile（D20）

- **隔离**：一套记忆 + 一套锚点 = 一个 profile（`AS_PROFILE` 隔离为独立目录与库文件 `profiles/<名>/memory.db`），跨 profile 不共享任何可变状态。
- **导入规则**：只允许整包导入，且导入内容标记「此会话的上下文仅供参考」、以 `imported` 起步。多 profile 编排设计见 [`records/47-profile-orchestration.md`](records/47-profile-orchestration.md)。

### B7-a 会话级信任等级（A9）

- **机制**：信任是会话的属性（`session_trust` 表），支持按会话切换「受信任 / 不受信任」（仅有 `/as-untrust`、`/as-trust` 人侧命令可改，模型完全不可感知阈值与开关）：
  - **受信任**（本机新建默认）：读、写正常；
  - **不受信任**：上行读记忆与对话照常，**全部写入（收尾沉淀、维护补记、`REVISE`）入 `pending_write` 队列**，共享结构操作（`merge`/`supersede`/标签操作）整段跳过；
  - 积压队列上限 `AS_PENDING_MAX`（默认 50），到线丢弃新写入并记审计；人可通过 `/as-writes [来源]` 筛选，并以 `/as-adopt`、`/as-dismiss`、`/as-adopt-all`、`/as-dismiss-all` 处置；
  - 切回 `trusted` 只影响之后，不自动追认既有积压；不受信任会话仍可正常触发 `REDACT` 剔除（安全动作不归写入）。

### B8 会话 ⟂ 会话（上下文隔离，记忆共享）

- 上下文按宿主 session 文件严格隔离，互不可见；记忆在同 profile 内跨会话共享（A3）。因此污染扩散风险全部由 B4 来源定级、B7-a 信任队列与交涉修正兜住。

### B9 子代理 ⟂ 主 AI

- 原则上子代理应以不加载 AS 的独立上下文运行，只返回结构化摘要而不直写主记忆。当前 `pi-coding-agent` 扩展 API 未提供子代理创建接口，此边界在宿主支持编排后重开。

### B10 归档 ⟂ 上下文（只约束 AI）

- **对 AI**：归档不参与自动注入；`archive(key)` 必须按 `年→月→周→天→时` 分阶段下钻；`archive(q)` 仅检索指针表索引区（`title + summary`），单次 ≤3 条 × ≤300 字（弱于 `key` 同层 3×400 字原文）且每轮限 2 次，不构成全文直查破口。
- **对人**：可直接查阅任意会话原文（A6）。

## 3. 隔离的传播规则

1. **来源传播取最不可信**：关联带出时，一跳有效 `trust` 取连接双方最低值。
2. **抑制不参与联想**：`linkedEntries()` SQL 要求边两端均处于 `state = 'active'`，被 `suppressed` 的条目在一跳、二跳联想中均不带出（恢复 `active` 后边自动恢复效力）。
3. **裁决不继承**：单次批准仅对当次变更生效，不因过去批过类似改动而放宽后续审批。

## 4. 内在冲突裁定总结（C1–C7）

| # | 冲突 | 结论 |
|---|---|---|
| C1 | 审批隔离 vs 判断力 | 坚持完全隔离（A1），靠反思质量与历史变更链补足 |
| C2 | 黑盒 vs 可调试 | 对主 AI 黑盒，对人白盒（`/as-*` 命令 + `view.ts` + 审计链） |
| C3 | profile 隔离 vs 连续性 | 整包导入且降级为参考资料（A4） |
| C4 | 归档隔离 vs 补救效率 | 仅约束 AI 分阶段检索，人对会话原文直接可读（A6） |
| C5 | 子代理隔离 vs 结论可信 | 待宿主支持子代理后要求结构化摘要与不确定性声明 |
| C6 | 常态畅通 vs 闸门判定 | 不设静态阈值（A7）：模型判风险 + 代码映射后果 + 硬不变量不谈判 |
| C7 | 自动剔除 vs 误伤收场 | 发送视图现算 + 作废派生沉淀 + 极低触发率（A8） |

## 5. 三个硬不变量（不可协商）

1. **L0 不可变**：编译进代码常量，任何接口不可修改。
2. **外部/导入来源不得直改 L1/L2**：`addAnchor()` 白名单仅允许 `human` 与 `maintenance`。
3. **`origin` 不可被自述覆盖**：`origin` 只由代码服务写入，模型无法把推断结果标为 `user`。
